## 00:0x–00:2x AGT-H1（rideRef 工具参数，先行两工具）交付 → Review

**新增 `src/chat/chat-ride-ref.ts`（rideRef 合同 + 解析 + 候选 + 确定性话术的唯一点）**：`rideRef` 三选一 `{date}|{ordinal}|{rideId}`（parse 强制恰好一个键）；四种结局 `resolved / ambiguous(same_day_multiple) / need_reference / not_found(date_not_found|ordinal_out_of_range)`，后三者都带 `candidates`（≤5、按出发时间倒序、含 `rideId/dateLabel/timeLabel/distanceKm/hasPower/hasHeartRate`）。

**关键设计判断（都写进代码注释 + AI-Spec §5.1）**：
1. **"不默认取最新"落在工具层，"要不要默认"落在编排层**：工具无 rideRef → `need_reference`；编排层要把"最近一次"写下来就显式注入 `{ordinal:-1}`。这样默认行为从"隐含"变成"可观测、可被 H2 换成问用户"。
2. **日期同日多条 = ambiguous，不再取最晚**（这是"另一次问不到"的根因）。**三路口径要提前讲清**：同日两条时"点选 rideId 唯一 / 序数唯一 / 日期天生无法唯一"——细规划里"三路全部唯一定位"逐字不成立，验收口径按"每条路径行为确定且不猜"。
3. **`rideRef` 在 parse 层可缺省**：若缺省即判非法，`need_reference` 这条路永远走不到（模型拿不到"你想分析哪一次"的出口）。
4. pending 是**结果不是错误**：`RideReferencePendingToolResult` 独立于 `ChatToolResult`，循环回执 `status:"reference_pending"` → agent 零模型候选话术（`TOOLS_REFERENCE_NEEDED`），避免落进 no_match 的"暂时无法回答"。
