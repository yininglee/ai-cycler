### 关键发现（待决策）：生产模式下会话 cookie 带 `Secure`，纯 HTTP 局域网会失效
- `src/auth/session.ts:66`：`const secure = process.env.NODE_ENV === "production" ? "; Secure" : "";`
- 后果：`next dev` 下 cookie 无 `Secure`，手机 `http://192.168.x.x:3000` 正常；切到 `next start`（NODE_ENV=production）后 cookie 带 `Secure`，浏览器在**非安全源**（局域网 IP 的 http）会**丢弃**该 cookie → 无 session → `/api/chat` 回到 404（已 revert 的 `getRequestSession`）。**手机端会比 dev 更差。**
- 实测证据：`curl -D -` 生产响应含 `set-cookie: ...; HttpOnly; SameSite=Lax; Path=/; Max-Age=2592000; Secure`；对 `localhost` 请求 curl 会存 cookie，对 `http://192.168.31.62` 请求 curl **不存**（jar 为空）。浏览器同理（localhost 被视为可信源，局域网 IP 不是）。
- 候选方案：(a) 把 `Secure` 改为环境变量门控（默认仍 Secure，本地演示可显式关掉）；(b) 生产用 HTTPS（反代/自签证书）或隧道（cloudflared/ngrok）；(c) 暂不处理，仅本机演示。
- 注：`/api/chat` 404 属已知设计（session 修复此前按用户要求撤回），与本次构建无关。
