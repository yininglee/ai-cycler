## A5 验收期三处回归缺陷（用户三张截图暴露）+ 全部修复实证

用户实测发现：①「我最近骑行数据怎么样？」答"需要先取得已授权的只读工具结果…不会猜测骑行数据"；②「上次我的骑行心率怎么样？」连问三次才成功，前两次"对话服务暂时不可用"；③「上次我的骑行心率多少？」答成"最近一次可用骑行记录的日期是 10/5"。

**关键判断：三处都不在分类器**——日志显示 intent 全判对（aggregate / ride_summary / history_compare），问题在前后端与超时配置。

- **R1 前端兜底猜答案**（截图③）：`chat-home.tsx` 服务端失败时回退 `replyToChatInput`（M1 本地正则），`/(最近|上次).*(骑行|记录)/` 命中即答日期。**违反 D-A2「诚实失败优于错误猜测」**——服务端早已诚实降级，前端还留着正则硬猜。已删除 `replyToChatInput`/`classifyInput`（原地留退役说明），失败统一 `CHAT_UNAVAILABLE_REPLY`。
- **R2 超时 8s 过紧**（截图①②）：主链路走硅基流动，默认 `SILICONFLOW_CHAT_TIMEOUT_MS=8000`；实测 4.5/5.3/7.4/8.17s，9.2s 直接 MODEL_TIMEOUT。改 8s→15s（上限 25s 不变），`CHAT_PROVIDER_TIMEOUT_MS` 同步（只作用已退役的通用 HTTP provider），分类器 8s→12s（实测 ≤4.2s，但失败是终局降级无兜底，代价更高）。**实证：修复后 `duration=8170ms` 成功**——旧阈值下必失败。
- **R3 aggregate 无口径答"我不会猜测"**（截图①）：`classifyAggregateQuestion("我最近骑行数据怎么样？")` 返回 null（无累计/本周/最近一次+时间关键词）→ 回落 `templateReply` 的 default。新增 `aggregateOverviewReply`（只陈述已确定事实 + 收窄引导），日志 `kind=none`→`kind=overview`。
- **验证**：tsc 0 error；全量 **704/704**（+2 回归测试：指标问法不得降级为日期、aggregate 无口径须给总览）；真实请求三条分别验证 R3 总览、R1 服务端侧（168/184 bpm）、R2（8170ms 通过）；`history_compare` 未被 v0.4.1 条件误伤。
- **重点：三处修复不碰 Prompt/数据集 → A5 的 83/83 继续有效，无需重跑。**
- 经验：**"错在哪一层"比"错了"重要**。三张图看着都是"AI 答错"，实际是前端兜底、超时配置、服务端兜底模板三个不同层。`kind` 轴/日志分层在这里同样适用。
- 另：curl 验 API 必须先造签名 cookie（DEV_SECRET 硬编码在 `src/auth/session.ts`），否则一律 404；`--noproxy '*'` 必须加，否则本机代理会返回 502。
