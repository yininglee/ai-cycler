- 19:40 底部导航 tab 切换加「立即反馈 + 加载态」。用户反馈：首次打开 demo 时切换 tab 加载太久，点击后应有立即反馈，先跳到目标页并显示加载状态。

  **根因**：① `/` 是静态路由，但 `/import`（读 cookie + 仓储 listRides）与 `/chat`（读会话 + 仓储）都是**动态路由**，客户端导航必须等一次服务端往返；② 项目里**没有任何 `loading.tsx`**，没有路由级 Suspense 边界，所以点击后界面完全定格，零反馈；③ `next dev` 首次访问才按需编译该路由（数秒），把等待进一步放大——「首次打开 demo」正是这个场景。

  **方案（两层）**：
  1. **客户端乐观加载层（保证「立即」）**：底部导航由服务端静态 JSX 改为客户端组件 `app/components/bottom-nav.tsx`。点击时立刻 `setPendingKey(key)`，乐观高亮目标 tab（`shownKey = pendingKey ?? active`）并铺一层 `position: fixed; z-index: 19` 的目标页骨架；`usePathname()` 变化后 `useEffect` 清掉乐观态。底部导航 `z-index: 20` 高于加载层 → 导航保持可见可点，可连续切 tab。另加 8s 兜底超时防卡死；`onPointerEnter`/`onTouchStart`/`onFocus` 时 `router.prefetch()` 预热目标路由。
  2. **路由级 loading.tsx（保证流式渐进）**：新增 `app/import/loading.tsx`（active=rides）、`app/chat/loading.tsx`（active=partner）、`app/rides/[id]/loading.tsx`（active=rides）。**故意不加 `app/loading.tsx`**——根段边界会给 `/profile` `/demo-events` `/share/[id]` 套上 active=today 的骨架，导致「今日」tab 错误高亮，而 `/` 本身是静态路由不需要它。

  **防闪烁细节**：热导航服务端只要 ~80ms，若加载层立即不透明就只是闪一下。故 CSS 用 `animation: route-loading-fade .18s ease-out .12s both`——元素立即挂载（不占位跳变），120ms 后才淡入；路由够快时用户根本看不到这层。

  **循环依赖规避**：`app-shell.tsx` 现在要 import `BottomNav`（客户端），而 `BottomNav` 又要复用骨架组件。为避免 `bottom-nav → route-loading → app-shell → bottom-nav` 成环，把 `Brand` 从 `app-shell.tsx` 抽到独立 `app/components/brand.tsx`，`app-shell.tsx` 用 `export { Brand } from "./brand"` 保持向后兼容（`page.tsx`/`import/page.tsx`/`profile/page.tsx`/`chat/*-preview` 等 6 处 import 路径无需改动）。`RouteLoadingBody` 只依赖 `./brand`，故 server/client 两侧都能安全复用。
