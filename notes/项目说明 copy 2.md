>
> **「受约束 AI」一句话定义**（速览卡与 01 章均引用）：  
> AI 不直接接触原始数据、不自由生成事实；由确定性规则引擎把原始数据计算成「可验证的事实（Claim）」，LLM 只负责把这些经批准的事实组织成用户能理解的语言。AI 失败、越界或幻觉时，系统自动降级回确定性输出。

## 01 背景与洞察

**本节目标**：讲清「为什么做」与「我看到了什么别人没看到的」。落到核心洞察「受约束 AI」。

### 1.1 痛点：骑了，但不知道骑得怎么样

- 全国骑行用户超 1.3 亿，绝大多数是业余爱好者，每周骑 2–4 次，用行者 / 黑鸟 / 码表记录轨迹。
- 面对一堆数字（均速、里程、爬升、心率、功率），不知道它们意味着什么、彼此什么关系、反映自己什么水平。
- 三个典型困惑：我骑了三个月到底有没有进步？今天比上周好还是差？我的水平算什么水平？

**素材占位**：`[截图：行者/黑鸟的数据详情页，展示"只有图表没有解读"]`

### 1.2 市场窗口

- 骑行人口爆发 + 社交驱动超越训练驱动 + AI 运动教练心智成熟 + 骑行垂类 AI 仍空白。

### 1.3 现有产品不足（对比表）

| 维度      | 行者    | Keep    | Strava | 本项目                |
| ------- | ----- | ------- | ------ | ------------------ |
| 骑行数据记录  | ✅ 专业  | ✅ 基础    | ✅ 专业   | ❌ 不自建记录（拉取、聚合码表记录） |
| AI 数据解读 | ❌     | ⚠️ 泛化   | ⚠️ 英文  | ✅ 中文专项·能力驱动        |
| 体能评估    | ⚠️ 图表 | ⚠️ 通用评分 | ✅ 付费   | 后续专项准入             |
| 中文支持    | ✅     | ✅       | ❌      | ✅ 原生               |

### 1.4 核心洞察：受约束 AI

- **一句话立论**：AI 解读最大的风险不是"不会说"，而是"胡说"。
- 直接让 LLM 读原始骑行数据会带来三个不可接受的问题：数字不可验证、结论不可追溯、失败时无退路。
- 所以我的解法是「受约束 AI」：**确定性规则引擎是唯一事实源，LLM 只做语言表达**。
- 这一洞察决定了下文所有架构选择。

**素材占位**：`[图：一张对比图——"直接让 AI 分析数据" vs "受约束 AI"两条路径]`

### 1.5 从痛点切入到产品全貌

- 1.1–1.4 聚焦「骑行数据翻译」这一个最痛的切入点，因为这是差异化最大、最先交付的模块，也最能体现「受约束 AI」的价值。（骑行数据是进行骑行运动的用户社交分享和讨论最频繁的内容质疑，有了单次骑后解读，后续的骑行水平能力评估和训练计划定制都有了基础和依据，骑行水平能力评估需要通过固定时间范围内的多次骑行数据进行计算评分，骑行水平能力评估是决定训练计划定制的因素之一）
- 但「受约束 AI」并不只服务单次数据翻译——它同样适用于「AI 伙伴对话」「分享文案生成」等所有 AI 触点，是贯穿整个产品的设计哲学。
- 下章展示本项目最终的产品定位与完整能力版图，以及为什么 MVP 阶段只能交付其中一部分。

## 02 产品定位与范围

**本节目标**：讲清「做什么」与「不做什么」——产品抽象能力和范围管理能力。

> 承接 01 章切入的「骑行数据翻译」痛点：本项目最终定位覆盖更广的能力版图，本章一次性说清楚全貌与 MVP 取舍。

### 2.1 产品定位

- 骑行数据翻译官 + AI 骑行伙伴 + 社交催化剂。
- 不是冰冷的训练教练，而是懂你、鼓励你、把数据变成故事的朋友。

### 2.2 六模块全景与实际交付

- 六模块全景：数据接入 / 数据看板 / 骑后 AI 解读 / 社交分享 / AI 骑行伙伴 / 入门训练计划。
- **诚实标注**：本项目实际交付的核心闭环是「导入 FIT/GPX → 可靠事实与图表 → 骑后 AI 解读 → 分享预览意愿」，以及「AI 骑行伙伴对话 Agent」。分享导出、训练计划、水平评估为后续阶段。

**素材占位**：`[图：六模块能力覆盖矩阵，标注已交付/规划中/未开始]`

### 2.3 MVP 取舍原则

- 不建骑行记录器（用户继续用行者/码表/Garmin，只导入数据）。
- 不承诺训练处方、恢复天数、医疗结论（安全红线）。
- 「只做单次骑行数据解读，不做「骑行水平评分」（单次均速/里程/爬升受路线、风、体重等干扰，单次骑行数据无法真实反映骑行水平，会误导用户）——详见 07 章决策复盘。

## 03 核心设计一 · 骑后 AI 解读（受约束 AI 的落地）

**本节目标**：讲清「受约束 AI 是怎么实现的」——这是全项目技术/产品含金量最高的一章。

### 3.1 设计哲学：为什么不让 AI 直接分析数据

- 让 LLM 直接读原始数据 → 数字不可信、结论不可追溯、失败无退路。
- 我的选择：**确定性规则引擎 = 唯一事实源，LLM 只做语言表达**。
- AI 是"可关闭、可降级的表达增强"，不是系统的核心。

**素材占位**：`[图：受约束 AI 核心三原则——规则引擎唯一事实源 / Claim 白名单可追溯 / B0-first 兜底]`


### 3.2 L0–L8 分层数据处理管线

**核心内容**：数据从 FIT/GPX 变成可信结论，经过 9 个分层，每一层职责单一、可独立验证：

| 层  | 名称       | 职责                                         | 解决什么问题           |
| -- | -------- | ------------------------------------------ | ---------------- |
| L0 | 原始输入     | FIT/GPX、用户资料、历史记录                          | 格式与来源，不做推断       |
| L1 | 标准化时序    | 统一时间轴、单位、缺失/暂停标记                           | 数据可用且口径一致        |
| L2 | 确定性指标    | 速度/时间/海拔/坡度/功率/心率/踏频/区间/峰值功率               | 由纯函数生成事实，LLM 不重算 |
| L3 | 质量与解读门   | available/partial/insufficient/unavailable | 数据不足时隐藏而非硬算      |
| L4 | 分段/事件/关系 | 巡航段、爬坡段、共变/对比/权衡关系                         | 跨指标关系的确定性来源      |
| L5 | 原子 Claim | claimId + 事实 + 证据 + 限制                     | 每句结论可追溯          |
| L6 | 解读计划     | 重点维度排序、输出预算                                | 认知增量优先，避免指标罗列    |
| L7 | LLM 表达   | 一句话标签、整体评价、维度解读、行动建议                       | 只组织语言，不产事实       |
| L8 | 校验与呈现    | Schema/Claim/数字/安全校验 + 降级                  | 失败可定位删除，保留 B0    |

**要点**：强调「确定性计算与 AI 表达的彻底分离」——模型看不到原始曲线，只能看到经批准的 Claim。

**素材占位**：`[图：L0–L8 管线分层图（Mermaid）]` + `[截图：一个真实骑行记录的 AI 解读结果页]`

### 3.3 Prompt 设计与模型选型

- Prompt 职责边界：只理解结构、组织语言、区分事实/表现/能力/意义，**禁止重算数字、补缺失值、发明 Claim**。
- System Prompt 承载规则，User Prompt 接收结构化输入 + 修复指令 + 上一次输出。
- 模型选型：Coze Workflow 作为无状态表达节点；默认快速模型，深度思考独立对照（不混跑）。

### 3.4 兜底设计（B0-first）

- **B0 确定性事实报告**：AI 未配置、超时、Provider 错误、校验失败时，用户永远拿到确定性事实，绝不空白、绝不猜测。
- **D0–D4 五级降级**：完整回答 → 部分降级 → 受限修复 → 确定性模板 → 安全停止。
- **一次受限修复**：首次校验失败只允许一次删除违规内容，仍失败则降级。

### 3.5 界面交互流程（用户实际走过的路径）

> **本节目标**：把抽象架构落到用户视角——展示用户从「打开一条骑行记录」到「读完 AI 解读」的完整交互流，承接 06 章的交互设计纵深。

| 步骤       | 用户看到                              | 背后发生了什么                            | 关键设计决策                      |
| -------- | --------------------------------- | ---------------------------------- | --------------------------- |
| ① 进入详情页  | 三 Tab（摘要/分析/数据）+ 顶部「生成 AI 解读」入口   | 无 AI 触发，事实与图表已就绪                   | 入口不抢眼，让用户先看事实再看 AI          |
| ② 点击入口   | 进入生成状态页：准备事实 → 识别表现 → 组织解读 → 校验输出 | 编排层依次执行 L0–L8 管线                   | 状态页只显示真实步骤，骨架占位固定尺寸，绝不展示半成品 |
| ③ 完成     | 解读抽屉/长页：结论 → 证据图表 → 解读正文          | 通过校验的候选输出 + 视觉引用                   | 结论先于证据，文字-图表可双向定位           |
| ④ 用户继续操作 | 可切换默认/展开模式、查看证据抽屉、跳分享预览           | 服务端 cache 单键 `rideId`，重开 19ms 缓存秒开 | 默认只展示 3 个重点维度，展开后全量；不浪费用户时间 |
| ⑤ 失败/降级  | 收到 B0 确定性事实报告，附原因与重试入口            | 任意一步失败/超时/校验不通过                    | 用户始终拿到事实，AI 是增强而非核心         |

## 04 核心设计二 · AI 骑行伙伴对话 Agent

**本节目标**：讲清「对话 Agent 的架构与最有故事性的决策」——混合意图路由的演进。

### 4.1 双链路架构与分层

- 两条独立 AI 链路：`ride_analysis_v1`（骑后解读 Workflow）+ `ride_chat_v1`（对话 Agent）。
- 分层原则：**Agent = 服务端编排循环，扣子 Workflow 只是被调用的无状态表达节点**。
- 意图路由、工具调用、数据投影、输出校验、降级全部在服务端确定性执行；LLM 只负责"组织语言"。

**素材占位**：`[图：双链路架构图（Mermaid）——编排层/表达层分层]`

### 4.2 混合意图路由（核心决策，最有故事性）

**演进故事**（这是本章的叙事高潮）：

1. **起点：纯规则路由**——用正则匹配意图。上线后暴露 6 个结构性缺陷：
   - 「骑行中」在"我在骑行中"（危险）和"最近的骑行中"（历史查询）里语义相反；
   - 宽词「骑了」误吞聚合/历史/能力等意图；
   - 空 Claims 时模型注定无法通过校验；
   - 等等。
2. **根因**：正则没有语境，宽词相互吞噬，路由粒度不等于能力粒度。
3. **解法：混合意图路由**——
   - **L0 规则层**：只拦 100% 确定的红线（急症/越权/注入）和高置信聚合，零成本零延迟；
   - **L1 LLM 语义分类器**：小模型输出结构化意图标签（11 类），失败/超时降级回规则；
   - **L2a 场景 Workflow**：确定性场景（单次解读/历史比较/聚合）走固定工具链；
   - **L2b 自主工具循环**：开放复合问题（如"距离最远那次心率怎么样"）由模型在只读工具白名单内自行组合调用。

**要点**：强调「意图标签 ≠ 路由」的解耦设计——分类器决定"用户想干什么"，服务端权威映射决定"谁来答、怎么取数"，两层各自演进互不牵连。

**素材占位**：`[图：混合意图路由架构图（Mermaid）]`

### 4.3 会话内上下文与指代消解

- 最多 6 轮白名单摘要（只传用户问题 + 路由 + 骑乘锚点日期，不传历史数字）。
- 骑乘指代解析：「本次/这次」不默认等于最新记录，无锚点时确定性澄清。
- 明确边界：**会话内指代消解，不是跨会话记忆**。

### 4.4 安全与隐私

- 原始 FIT/GPX、精确坐标、完整时序、文件名、密钥**永不进入**模型投影或日志。
- 私有对象按 session owner 校验；工具只读 + 白名单 + 参数枚举 + 越权拦截。
- 记录删除级联删除分析、历史快照、会话摘要。


### 4.5 界面交互流程（用户实际走过的路径）

> **本节目标**：把抽象的混合意图路由落到用户视角——展示用户从「打开对话」到「收到答案」的完整交互流，体现规则 + 分类器 + 自主循环在用户端的统一感受。

| 步骤       | 用户看到                           | 背后发生了什么                                                     | 关键设计决策                  |
| -------- | ------------------------------ | ----------------------------------------------------------- | ----------------------- |
| ① 进入聊天页  | 顶部「新对话/对话记录」+ 三个固定快捷问题 + 底部输入区 | 加载 session 摘要、对话历史（仅本地 localStorage）                        | 快捷问题降低首次使用门槛，固定三个而非随机展示 |
| ② 输入问题   | 输入框 + 快捷问题区 + 历史对话             | 网关校验长度/频率/控制字符                                              | 注入/超长/超频一律拒绝，绝不传给模型     |
| ③ 路由分发   | 极快响应或思考态                       | L0 规则命中（红线/聚合/身份）→ 零调用直答；未命中 → L1 分类器（11 类意图）；失败/超时 → 降级回规则 | 用户感受不到分层，但"看起来像一个人"     |
| ④ 工具调用   | 状态行显示「正在获取本次骑行数据」              | 服务端 session + owner 校验 → 调只读工具（白名单 + 参数枚举）→ 投影回模型           | 模型看不到原始数据，只看到 Claim 投影  |
| ⑤ 收到答案   | Chat 气泡回复（≤600 字），含数字与「点击查看证据」 | 表达层返回 → 服务端校验 Schema/路由一致性/Claim 引用 → 修复或降级                 | 数字必须能在 Claim 集里找到来源     |
| ⑥ 红线/失败态 | 确定性安全/边界/域外回复                  | 急症/越权/注入/域外 → 固定模板，绝不调模型                                    | 关键时刻不让 AI 自由发挥          |

**典型场景对照**（让读者快速建立感受）：

| 用户问法          | 路由                                        | 体验特征                                                                   |
| ------------- | ----------------------------------------- | ---------------------------------------------------------------------- |
| "你好"          | `social` L0 零调用                           | 秒回，无需工具                                                                |
| "我总共骑了多少"     | `aggregate` L0 仓储聚合                       | 零模型，统计直答                                                               |
| "骑行中胸口疼怎么办"   | `safety_stop` L0 共现安全                     | 固定安全指引                                                                 |
| "本次平均功率"      | `current_ride` L1 分类 → `get_ride_context` | 走工具 + 表达层，数字带 Claim 引用                                                 |

## 05 AI 质量与测评方法论

**本节目标**：展示 AI 产品经理最稀缺的能力——**用工程化方法验证 AI 质量，而不是"看起来不错"**。

### 5.1 指标体系

- **硬门指标**（不可被平均分抵消）：Schema 合法率 100%、数值/事实忠实率 100%、原子能力越权 0、高风险安全召回 100%、医疗诊断/危险建议 0、注入/泄露 0、位置/隐私泄露 0。
- **六维质量 Rubric**：事实忠实 30% · 洞察价值 25% · 行动性 20% · 易懂性 10% · 语气 5% · 不确定性 10%。

### 5.2 数据集分层

- dev（快速诊断）/ regression（已知缺陷回归）/ blind（正式质量，冻结不可调参）/ red-team（安全对抗）/ product（目标用户真实任务）。
- 关键原则：blind 集对实现侧隐藏答案；小样本 100% 不得外推为永不失败。

### 5.3 协作测评流程（A–E 检查点）

- A 指标冻结 → B 测评集冻结 → C 执行授权 → D 人工盲评 → E 结论签署（GO/NO-GO/STOP-RETHINK）。
- 双人独立盲评 + 分差复核 + Cohen's kappa 一致性。

### 5.4 关键结果（真实数据）

- 骑后解读：81 槽正式稳定性门通过，P50/P95 = 10.7s / 18.9s。
- 对话 Agent：意图分类器 38/38 = 100%（red-team 6/6 零失误）；M3 里程碑固定集 （L2a确定场景workflow，不涉及自主agent测试）27/27 全绿。
- 工程回归：460/460 测试、typecheck、build 全过。

### 5.5 诚实的失败（复盘价值最高）

- 骑后解读**质量盲评签署 NO-GO**：综合 2.75 < 4.2 目标；洞察价值 +1.39（有增量）但**事实忠实 −2.17 低于 B0**。
- 复盘结论：失效可定位为 Prompt/规则缺口（方差类证据不在允许 Claim 集），不是方向错误。（另外，本人发现经过规则引擎后，输入的可用数据，即被允许的claim缺失较多，AI可解读数据较全量数据降低了近50%，后续需进一步优化数据处理规则）
- 这一节体现的是「不粉饰结果、能定位根因」的专业态度。

## 06 交互与视觉设计

**本节目标**：展示交互专业纵深——这是产品+交互复合背景的差异化优势，写得比一般作品集更深。

### 6.1 信息架构

- **三层内容模型**：摘要 Tab（相对轨迹 + 核心概要）→ 分析 Tab（时序曲线 + 区间分布 + 分段）→ 数据 Tab（按能力分组的事实明细）。
- **AI 解读的层级设计**：结论 → 必要证据图表 → 解读正文，正文内部遵循「事实 → 本次表现 → 本次体现的能力 → 用户意义」。
- **无数据即无模块**：缺数据的维度整体隐藏，绝不显示空卡片或占位 0——避免"有结构没内容"的信息噪音。

**素材占位**：`[截图：三 Tab 数据详情页，展示摘要/分析/数据切换]`

### 6.2 状态设计

- **AI 生成的完整状态机**：入口状态行（生成中/已完成/失败）→ 生成状态页（准备事实 → 识别表现 → 组织解读 → 校验输出）→ 解读长页/抽屉。
- **降级状态的用户表达**：AI 失败时展示 B0 确定性事实报告，附原因与重试入口，绝不展示半成品结论。
- **partial 语义**：部分数据缺失用「部分数据，仅供参考」轻量标记，而非静默省略或误导。

**素材占位**：`[截图：AI 解读生成状态页 / B0 降级态]`

### 6.3 可访问性

- **不只靠颜色**：所有区间、图例、状态均配文字/纹理提示，支持键盘/触控访问。
- **图表-文字双向联动**：点击曲线区段/标签定位到对应时间窗并高亮关联 Claim；文字引用反向滚动到图表证据——让"结论"和"证据"始终可互查。
- **无障碍文本不引入 Claim 之外的新数字**。

### 6.4 移动端适配

- 移动端优先，单列主阅读流，稳定纵横比。
- 图表允许横向拖动查看但**不拉伸、不横向溢出**。
- 重点检查尺寸：390×844、768px、1280px 三视口。
- AI 解读采用**底部 sheet / 桌面 modal** 的响应式容器，重开秒开（会话缓存）。

### 6.5 设计原则小结

- 结论先于证据；事实可追溯；信息密度优先于装饰；颜色永远有文字补充。

## 07 结果与复盘

**本节目标**：用数据收口，展示结果导向 + 反思成长。

### 7.1 量化结果汇总

- 工程：FIT/GPX 解析 + 18 项原子能力 + 20 个特征 + 三类 Claim 白名单 + 460 项回归全绿。
- 产品：M1 骑后解读闭环（含生产入口迁移 + 真实链路冒烟）；M3 对话 Agent 15/15 任务全验收，里程碑收口。
- AI 质量：81 槽正式门、分类器 38/38、M3 27/27（详见 05 章）。

### 7.2 关键决策复盘（选 3 个最有代表性的）

1. **为什么不设「骑行水平总分」**：单次均速/里程/爬升受路线、风、体重、停歇强干扰，会误导用户 → 改为多维能力画像，且单次与长期严格分离。
2. **为什么放弃纯规则路由**：正则没有语境、宽词相互吞噬 → 升级为混合意图路由（规则红线 + 小模型分类 + 自主工具循环）。
3. **为什么 B0-first**：AI 是可降级的增强而非核心 → 保证任何 AI 失败用户都有确定性事实兜底。

### 7.3 不足与反思

- 盲评 NO-GO：事实忠实不足，洞察性偏低，定位为 Prompt/规则缺口，修复循环暂停。
- 性能：同步 Provider 25 秒，未达 8 秒 P95 目标，成本不可观测。
- 数据持久化：本地文件仓储，未接生产 PostgreSQL。

### 7.4 下一步

- M2：社交分享导出 + 持久化。
- M4：骑行水平评估（能力画像，设计已完成）+ 入门训练计划（需专业审核）。
- 生产化：OIDC、成本可观测、模型对照选择。
