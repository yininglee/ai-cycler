> 规划日期：2026-10-08。Session 估算只用于控制颗粒度，不是工期承诺。

## 1. 价值闭环

用户导入 FIT/GPX 后，AI 解读不再围着"详情页平均数"打转，而是围绕**运动科学知识库定义的维度化关键指标**（配速的 VI、爬坡的 W/kg 与 VAM、心率的 EF 与有氧解耦……）组织证据，并为每个维度提供**基准分级参照 + 解读逻辑线索**，让"骑得怎么样、意味着什么"有更专业、更口径一致的解释。

## 2. 工作约定

- 继承 V2 全部工作约定：`Backlog / Ready / In Progress / Review / Blocked / Done / Paused` 七态；最多一个主 `In Progress` 或 `Review`；自检通过进 `Review` 并停止；只有用户明确验收才记 `Done`；每项验收汇报写在对应工作项下。
- **本轮不改变 V2 里程碑（R2-1/R2-2/R2-3）的完成数**，V2.1 是独立路线图；不动 V1 生产链，默认仍走 V1 引擎。
- **知识库替换为硬约束**：新知识库 `ride-kb-2.1.0` 上线后，旧 batch1 仅作只读归档，不再被任何链路引用。
- 每个派生指标 = "纯函数 + 固定点列单测 + 版本化 formulaVersion"，三者缺一不可验收。
- 本规划任务 ID 前缀 `V21`，与 V2 的 `RIDE-AI-*` 不冲突。

### V2.1-B：指标计算层补全（派生指标）

**目标**：新增 `src/domain/ride-derived-metrics-v21.ts` 纯函数模块，补全 20 个派生指标，逐个固定点列单测。

- `[ ]` **`V21-03` 配速 + 功率输出派生指标**：VI、前半/后半功率差、负分割、停歇占比、爬升/下降功率比、功率曲线扩展（5s/1min/5min/20min/1h）。
- `[ ]` **`V21-04` 爬坡 + 强度负荷派生指标**：爬坡 W/kg、VAM、坡度-功率匹配、爬坡功率衰减、有效爬升高度、相对强度 RS、每 TSS 耗时。
- `[ ]` **`V21-05` 心率 + 跨传感器派生指标**：EF、心率漂移口径对齐、心率恢复（受限）、有氧解耦 Pw:Hr、速度-功率比、心率-踏频关系。
- `[ ]` **`V21-06` 踏频派生指标**：踏频变异系数、功率-踏频关系、传感器对齐校验、坡度-功率匹配（跨传感器收口）。

每项退出条件（共同）：纯函数实现 + 固定点列单测通过 + `formulaVersion` 版本化；`V21-03` 额外把派生指标接到 Claim 构建（`buildRideCapabilityClaimsV2`）并补能力依赖。

### V2.1-C：输入口径切换与知识挂载改造

- `[ ]` **`V21-07` KB 指标覆盖矩阵上线**：新增指标覆盖矩阵（§6），作为模型输入口径准绳；字段覆盖矩阵降级为审计索引；模型投影层改白名单制（§6.3 三层进、其余不进），证据包层保留完整 Claim。

  - **待决策 D2（第③层"解读逻辑点名的过程事实"粒度，不必现在定死）**：默认**先全收**——停歇次数+单次时长、爬坡踏频、心率区间分布、功率曲线各时长、前后段对比都进投影；用长骑行样例（`demo-ride-2026-07-22` 等）实测模型可见体积，**超预算再按"与解读逻辑的相关性"裁剪**（有数据再裁，不预先拍脑袋）。裁剪规则同样由解读逻辑信号字段确定性推导，可复现。
