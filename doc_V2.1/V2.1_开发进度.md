### 2026-10-08 · demo 运行时修复 · 数字门范围语义（`REPAIR_FAILED / NUMBER_NOT_IN_CLAIMS`）

- **现象**：`?ai=v2` 真实模型调用报 `REPAIR_FAILED`，`failureCodes: ["NUMBER_NOT_IN_CLAIMS"]`（首轮 + 修复轮都卡数字门）。
- **根因**：V2.1 重新打开知识输入后，知识正文塞满基准分级**范围数字**（"VI 1.05–1.15"、"负分割 2–5%"、"VAM 800–1200" 等约 50 处）；数字门对知识正文只做精确相等，`extractNumbers` 把范围拆成边界点，模型转述范围中间值/概括值（"约 3%"、"约 0.8"、"约 1000"）被误判为编造。
- **修复**：`ride-output-validator-v2.ts` 新增 `extractNumberRanges`（把 `A–B` 解析为 `[min,max]`），知识侧数字匹配在精确相等外追加"数字落在所引知识正文范围内"；正文外的数字仍拦截。
- **验证**：`tsc --noEmit` 通过；`ride-output-validator-v2.test.ts` 新增 2 条（范围中间值通过 / 范围外数字仍拦截），37/37 通过；全量 **676/676**（674+2）通过。
- **待办**：真实模型重新跑一次验证 demo 效果（需 API key）。

### 2026-10-08 · 根因修复 · 派生指标丢失 + 跨维度引用（`CLAIM_NOT_IN_DIMENSION` / `NUMBER_NOT_IN_CLAIMS`）

- **现象**：demo-07-22 / upload-0312e501 报 `REPAIR_FAILED` + `[CLAIM_NOT_IN_DIMENSION, NUMBER_NOT_IN_CLAIMS]`；demo-08-20 每次都要过一次修复。
- **根因**：V21-07 `buildDerivedMetricClaimsV21` 的派生指标 supports 值（`power_variability`/`pacing_split`/`pacing_negative_split`/`aerobic_efficiency`/`power_curve`）与 key（`pacing.*`）不在 `PACKET_DEFINITIONS` 的 supports/keyPrefixes 里 → VI/前后半功率差/负分割创建后进不了任何 packet、被 `allowedClaims` 过滤**静默丢失**；EF 只挂 heartRateLoad、crossSensor 维度引用不到 → 模型看不到指标却要按知识正文解读，触发两个错误码。**确定性 bug，非模型不稳定。**
- **修复**（`ride-analysis-evidence-packets-v2.ts`）：`pacingExecution.keyPrefixes` +`"pacing."`；`powerOutput.supports` +`"power_variability"`（VI 共享）；`crossSensorCoordination.supports` +`"aerobic_efficiency"`（EF 共享）。
- **验证**：离线 dump 确认修复后 VI→[pacing,power]、EF→[hr,cross]、split/负分割→pacing；新增回归测试 1 条（证据包 8/8）；全量 **679/679**；typecheck 通过。
