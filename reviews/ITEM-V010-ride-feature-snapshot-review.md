# ITEM-V010｜RideFeatureSnapshot单次特征事实合同评审

> 日期：2026-08-20  
> 状态：`ACCEPTED`  
> 当前阶段：v0.1 证据型Demo / G1「Demo核心价值」  
> 边界：只建立单次确定性特征事实，不接入历史、模型、Prompt或扣子。

## 1. 工作项目标

基于已验收的`RideActivity v0.2`、`RideSeries v0.1`、`UserProfile v0.1`和`AtomicCapabilityProfile v0.1`，生成可复算、可引用、带`claimId/evidenceId`的单次骑行特征，为后续骑后AI多维解读提供事实输入；原始轨迹和完整时序仍只在规则/UI侧使用，不发送给模型。

## 2. 依据审计

### 2.1 已核对来源

- PRD 6.3：AI应解释本次骑行的意义，不平铺概要；速度/节奏、心率、功率、爬升和踏频按实际能力动态选择；亮点事件必须由确定性特征引擎识别；不可靠时不猜测。
- PRD 7.5.1/7.5.2：`RideFeatureSnapshot`不向量化，作为版本化规则事实层；上下文需保留能力、质量、允许claim和安全/隐私边界。
- PRD 7.6.1：先解析、质量校验、能力判断和特征计算，再由`AnalysisEligibility`决定是否调用模型。
- 版本路线图：V010属于v0.1 P0“特征与历史事实链”，验收要求特征可复算并有claim；历史比较与模型输出在后续切片。
- 研发指南：特征、规则、Schema分别版本化；不把原始时序发送给模型；未校准的冲刺/爬坡等高阶事件不在当前Demo放行。

### 2.2 冲突结论

未发现需要用户决策的实质冲突。`AnalysisEligibility`在PRD Workflow中作为后续组合门出现，但路线图和研发指南均允许先交付其确定性特征输入，因此本项只实现Snapshot，不提前决定模型是否调用。

## 3. 实现范围

### 3.1 合同

`RideFeatureSnapshot v0.1 / ride-feature-rules-v0.1`包含：

- `features[]`：维度、特征键、数值/单位、公式版本、输入序列或指标、样本量、置信度、`claimId`和`evidenceIds`；
- `unavailable[]`：不可用特征的稳定原因码和所需原子能力；
- 纯函数构建器和快照校验器，拒绝非法版本、重复键、非法claim、非有限值、缺少证据或可用/不可用冲突。

### 3.2 首版特征集合

| 维度 | 特征 | 最低门槛 |
|---|---|---|
| 速度/节奏 | 序列均值、总体标准差、变异系数、前四分之一与后四分之一均值差 | `speed`能力、有效序列≥5；前后差≥8 |
| 心率 | 序列均值、总体标准差、前后四分之一均值差 | `heartRate`能力、有效序列≥5；前后差≥8 |
| 功率 | 序列均值、总体标准差、变异系数、前后四分之一均值差 | `power`能力、有效序列≥5；前后差≥8 |
| 功率关系 | NP/平均功率比 | `power`、NP和平均功率均可靠且平均功率>0 |
| 踏频 | 序列均值、总体标准差、变异系数、前后四分之一均值差 | `cadence`能力、有效序列≥5；前后差≥8；不依赖时间戳/心率/功率/FTP |
| 海拔 | 最低、最高、海拔范围、累计正爬升 | `elevation`能力；范围特征有效序列≥5；正爬升沿用已有可靠指标 |

共20个候选键；在当前L3样例中20个可用，实际可用数量由记录能力动态决定。

> 注：这些是事实特征，不是“稳定区段”“爬坡事件”“冲刺事件”或训练评级。当前不输出任何未经真实样本校准的高阶事件。

## 4. 重要边界

- 无时间戳GPX仍可生成海拔特征；速度/节奏因原子能力关闭而不生成。
- 只要有可靠踏频，踏频特征独立可用，不要求时间戳、心率、功率、FTP或个人资料。
- 有功率无心率时可生成功率特征；有心率无功率时不生成功率特征。
- 不计算心率区间、功率区间、IF、TSS、训练负荷、恢复天数或训练处方。
- 首次骑行/历史不可比不在本项处理；历史比较留给`ITEM-V011`，不会由本项产生趋势。
- 不修改详情页UI，不把L1/L2/L3写入Snapshot，不调用模型/RAG/Function Calling。

## 5. 验收标准

- 同一输入重复计算得到相同Snapshot、公式版本、claim和evidence；
- 每个可用特征均为有限值，拥有稳定claim和至少一个evidence；每个不可用特征拥有原因码；
- 质量不足、样本不足、无时间戳和非法记录不会被模型或特征层猜测补齐；
- 100%通过类型、快照合同、组合边界和回归测试；生产构建通过；
- 输出脚本可重算代表性Fixture矩阵，且不暴露精确坐标、文件名或原始轨迹。
