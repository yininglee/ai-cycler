## 3. 发现

### 3.1 B0 能力判断异常

`RA-AUTO-010` 和 `RA-AUTO-015` 是室内传感器-only fixture，分别保留可靠心率或功率，但没有路线距离。旧 `buildRideCapability` 以 `distanceM` 缺失直接设置 `analysisMode=rejected`，`buildClaims` 随后返回空 Claim，造成 B0 声称数据缺失/损坏。

这不是传感器质量失败，也不是 B2 模型输出问题；是旧 B0 的整条记录门控过严。

### 3.2 运行时超时与降级

正式批次记录首轮超时 20 次，P50/P95 为 `15002.862ms / 23541.581ms`。现有实现已满足：首轮超时立即 B0、修复超时立即 B0、每槽最多两次调用、无第三次调用。

在本运行时修复切片形成时，本项不把 `AI_ANALYSIS_TIMEOUT_MS` 从 15 秒继续放宽；当时的结论和后续15秒运行证据均按原配置保留。平台实际响应已经超过 Demo 的 8 秒目标，任何放宽都必须由单独的预算决定和复测证据支持。成本、精确模型 ID、区域和首 Token 延迟仍不可观测。用户后续通过 `DEC-069` 单独接受了 Demo 当前同步等待上限改为25秒，这不改变本段历史结论。

## 4. 实施修复

1. `buildRideCapability`：允许缺少路线距离但存在可靠时间/速度/心率/功率/踏频/爬升事实的记录进入 `basic`，不把局部缺失升级为整条 rejected；真正无可用分析事实的记录仍保持 rejected。
2. B0 基础摘要：无完整路线距离时改为说明“缺少完整路线距离背景”，不再输出数据损坏结论。
3. B0 高亮：室内仅心率/仅功率的 basic 记录优先展示其可用传感器事实，保持 Claim 和 evidence 可追溯。
4. 运行时回归：固定 15 秒配置上限；固定首轮超时和修复超时都立即降级，禁止第三次 Provider 调用。

### 6.1 解读质量规则与回归覆盖

已将四条规则写入 Prompt v3.1.2：

1. 有可靠且有意义的特征时，不能退化为纯事实清单；
2. 没有安全、直接的解释价值时，允许准确罗列事实或省略维度；
3. 通用行动使用 `kind=general` 且 `basisClaimIds=[]`，与绑定 Claim 的 `kind=grounded` 明确区分；
4. `overallAssessment` 只整合结论必要的 1–3 组维度，并要求主题 Claim 完整引用，不为凑维度重复所有指标。

输出合同校验增加非阻断质量警告 `FEATURE_EVIDENCE_AVAILABLE_NOT_USED`：当可靠的波动、首末变化、CV 或标准化功率比等特征可用、但输出只使用基础事实 Claim 时，标记质量不足而不阻断合法降级；确实没有这类特征时，事实罗列仍保持合法。
