## 1. 本次要解决的问题

旧版把当前用户骑行数据、体能档案和通用知识放进同一条向量检索链路，并固定模型品牌、允许模型生成后“自动修正数字”。这会造成精确记录误召回、旧档案覆盖新档案、权限与删除治理困难，以及数字被改但结论仍错误等风险。

## 2. 问题—修订映射

| 原问题 | v1.2处理 |
|---|---|
| 用户数据和知识统一RAG | 用户数据走结构化数据库/只读工具；RAG只检索审核知识 |
| Agent结构不明确 | 一个用户可见Agent + `ride_analysis_v1`/`ride_chat_v1` |
| 规则与模型责任重叠 | 规则负责事实、阈值、安全；模型负责意图和表达 |
| 模型自行算数/补数 | `RideContextSnapshot`事实白名单 + `claim_id` + 输出后校验 |
| 固定DeepSeek和静态成本结论 | B2/B3同条件基准选型；当前成本明确为T0 `NOT_RUN` |
| 只有宽泛质量指标 | 增加硬门槛、质量Rubric、5人产品验证和B0–B3协议 |
| 缺少输入攻击与隐私边界 | 自由文本/RAG/工具结果视为不可信数据；服务端权限和脱敏日志 |
| 失败只提示重试 | D0–D4：降深度、一次修复、B0模板、安全停止 |
| 训练计划与Demo边界冲突 | 多周处方型训练计划后置，需独立专业审核与专项Gate |
