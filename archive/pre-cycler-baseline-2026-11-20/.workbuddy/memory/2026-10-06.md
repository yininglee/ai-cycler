## 骑后解读 V2 成本分析与输入压缩（用户只接骑后解读收尾线）

- 边界确认：用户只接「骑后解读收尾」线（EVAL-01 五决策点 + AUDIT-01 两缺口），暂不动手；对话 Agent V2 线不接。
- 成本结论：0.2 元/次合理，**成本 85% 在输入 token**（~12 万字符证据包），不在模型单价。硅基流动 DeepSeek-V4-Flash 国内 ¥1/¥2（M）、官网 $0.22/$0.66（M）双轨，需用户账单实核准。
- 输入压缩三档：① prompt 瘦身投影（剥离 sourceRefs/evidenceIds/key/provenance/formulaVersion/aggregatedFromCount + 顶层 analysisRunId/userScope/privacyFlags/inputStats + 知识 sourceRef/applicableDimensions/retrievedAt）→ 零风险（校验器用内存完整 input，不看 prompt 文本）；② 知识库 applicableDimensions 跟 S2-06 收紧（8 条知识仍全选中，因每条都命中现存维度）；③ value/unit 兜底策略。
- **批量评测缓存红利**：`analysisRunId` + 知识 `retrievedAt`（now 时间戳）是缓存杀手，导致同一案例反复跑 prompt 字节级不一致→缓存永远不命中。剥离后命中缓存（命中价约输入价 1/3），叠加瘦身约省 70%。硅基流动 DeepSeek 自动上下文缓存已确认（V4-Pro 命中 $0.44/M）。
- 知识库关闭三程度：A 半关（只不附带，prompt-input 不一致会埋雷）、B 全关（动 5 处=动产品资产=重评）、C 软关（feature flag + prompt 明示）。结论：无「不重评就干净关闭」路径，建议先量化 knowledgeReference 占比再定。知识正文只占输入 2-3.5%，省钱非主因。
- **新增脚本** `scripts/export-v2-model-input-sample.ts`（node --experimental-strip-types 跑）：真实走 V2 链路导出「货架 input-full.json / 精简 input-slim.json / 文字清单 prompt.txt」对照。两轮实测：① l3-power-preview fixture（14 claim/1 问题）完整 13627→精简 8124 字符，省 40.4%；② **demo-ride-2026-07-22 真实长骑行（107 claim / 8 知识 / 6 维度）完整 119,064→精简 70,186 字符，省 41.1%（48,878 字符）**，prompt 总 122,232 字符。产物目录 `output/v2-input-sample/` 与 `output/v2-input-sample-demo/`。**关键印证**：8 条知识全量附带（S2-06 未收紧 applicableDimensions）；剥离追溯字段近半输入；剥离 analysisRunId+retrievedAt 是批量评测缓存命中的前提。
- 脚本已参数化（`node ... scripts/export-v2-model-input-sample.ts <rideId>`）。第三轮 `demo-ride-2026-08-20`（通勤含心率、无功率）：59 claim / 3 知识 / 4 维度，完整 57,564→精简 33,019 字符，**省 42.6%**。压缩比例稳定 41–43%，与数据量无关；知识按维度命中（无功率故只附 3 条）。
