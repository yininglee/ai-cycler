# AI 骑行伙伴旧交付体系归档

> 归档日期：2026-08-27
> 状态：只读历史证据，不再作为后续开发依据，也不继续维护内容。

## 归档原因

旧体系把研发方法、版本 Gate、当前状态、追加式日志、决策记录和逐工作项评审拆散在多个长文档中。它完整记录了项目从 G0 到当前 v0.1 Demo 的过程，但日常恢复成本高，部分“当前状态”指针已经落后于实际代码和最近验收。

从 2026-08-27 起，后续开发统一依据仓库根目录的五份文档：

1. [`项目说明_AI骑行伙伴.md`](../../项目说明_AI骑行伙伴.md)：项目真相、文档权威顺序和历史追溯入口；
2. [`技术方案_AI骑行伙伴_v1.md`](../../技术方案_AI骑行伙伴_v1.md)：当前架构、数据流、边界和质量策略；
3. [`VIBE_CODING_开发规划.md`](../../VIBE_CODING_开发规划.md)：分阶段范围、任务 ID、进入与退出条件；
4. [`开发进度.md`](../../开发进度.md)：唯一执行事实源、当前任务、证据和用户验收记录；
5. [`AI_AGENT_测评计划与记录.md`](../../AI_AGENT_测评计划与记录.md)：AI 指标、测评集、AI 产品经理协作、人工评分和正式测评结论。

产品需求仍以根目录 [`ai-cycling-amateur-prd.md`](../../ai-cycling-amateur-prd.md) 为产品意图来源；新技术方案和开发规划以 PRD 六大能力模块为主线，并结合当前代码基线与个人 Vibe Coding 任务颗粒度重新排序。旧路线图的版本、Gate、周期和“当前下一步”均只用于追溯，不是新开发顺序。若 PRD 与当前阶段范围冲突，按新技术方案与开发规划记录为延期项，不静默删除需求。

## 使用规则

- 日常开发不得从本目录恢复“当前任务”或复制旧路线图任务。
- 仅在追溯旧决定、验收证据、失败原因或历史版本矩阵时定向读取对应文件。
- 旧相对链接若因归档位置变化失效，以本 README、新项目说明和仓库搜索结果为准；不得为修复历史导航而改写旧事实。
- 发现历史事实需要更正时，在根目录 `开发进度.md` 追加更正或新 ADR，不回写旧记录。
