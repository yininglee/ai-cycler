# 骑行水平/能力评估模块设计

状态：`Review`
任务：`AI-CAP-01`
日期：2026-09-01
范围：独立用户级模块设计；不改生产代码、Prompt、Coze 或当前输出合同

## 1. 产品目标

本模块独立回答两个长期问题：

1. **相对自己**：多次可比骑行中，哪些能力正在形成、保持或变化？
2. **骑行水平**：在有经过校准且适用的人群基准后，用户在各能力维度处于什么阶段？

它不属于某一条骑行记录的 AI 解读，也不替代单次详情页。单次骑行只产生“本次能力体现”及其证据；本模块聚合多次质量合格、场景可比的记录，形成长期能力画像。两者共享确定性指标、质量门、Claim 和隐私规则，但使用不同的聚合合同、产品入口和验收 Gate。

## 2. 与单次骑后解读的边界

| 项目 | 单次骑后 AI 解读 | 骑行水平/能力评估 |
|---|---|---|
| 评价对象 | 当前一条骑行记录 | 用户在一个纵向窗口内的多次记录 |
| 核心问题 | 本次骑得怎么样、体现了什么能力表现 | 长期具备什么能力、是否变化、处于什么阶段 |
| 最小证据 | 当前记录中通过质量门的事实、分段和关系 Claim | 多条质量合格且通过可比性门的记录与聚合 Claim |
| 可用措辞 | “本次”“该区段”“这条记录中” | “近 30/90 天”“在 N 次可比记录中”“能力初步建立” |
| 禁止 | 把单次表现写成长期能力或水平 | 用不可比样本拼接趋势、用一次峰值代表长期能力 |
| 页面入口 | 单次骑行详情的“AI 解读” | 首页或个人页的独立“骑行能力”入口 |

单次解读中的“相对自己”只说明当前记录相对指定历史窗口的变化，不自动改变长期能力状态。长期模块可以引用单次记录作为证据，但必须重新执行纵向样本、可比性和稳定性门。

## 3. 首版能力画像

首版不生成综合总分，不使用“新手/中级/高手”等身份标签，也不做全球排名。能力画像按维度独立建立：

| 能力维度 | 长期回答的问题 | 单次证据来源 | 首版最低纵向条件 |
|---|---|---|---|
| 持续输出 | 是否能在可比窗口持续维持输出 | 功率连续窗口、MMP、稳定性 | 至少 3 次同口径记录，跨 ≥14 天 |
| 耐力/后程保持 | 较长骑行后段是否能维持节奏或输出 | 骑行时间、暂停、前后程速度/功率/心率关系 | 至少 5 次时长和路线负荷可比记录 |
| 爬坡表现 | 可比爬坡段中的持续输出与配速是否稳定 | 爬坡段、坡度、时长、功率/心率/速度关系 | 至少 3 个可比爬坡段，并按坡度和时长分层 |
| 节奏稳定性 | 同类路线或训练中的波动控制是否稳定 | 连续窗口、暂停后恢复、前后程差异 | 至少 3 次同类路线或训练 |
| 心率-功率效率 | 同等输出下心率反应是否出现稳定变化 | 同窗口功率、心率、环境与基线 | 至少 3 次且温度、强度区间和设备口径可比 |
| 踩踏表现 | 踏频分布与输出配合是否形成稳定模式 | 踏频分布、功率/速度关系 | 至少 3 次真实踏频记录且设备口径一致 |

这些门槛是待真实纵向样本校准的首版设计基线，不是直接上线的医学或训练标准。某一维度不满足条件时只降级该维度，不影响其他维度。

## 4. 数据与生成链路

```text
单次记录 L0-L5 Claim
  → 用户历史候选筛选
  → 记录/区段可比性判断
  → 按能力维度聚合
  → 稳定性、变化与置信度门
  → CapabilityProfileSnapshot
  → 受控 AI 解释
  → 用户级能力页面
```

`CapabilityProfileSnapshot` 至少包含：

```text
profileVersion, userId, generatedAt, comparisonWindow,
dimensions[] {
  capabilityKey, state, confidence,
  validSampleCount, requiredSampleCount,
  comparisonScope, trendDirection,
  evidenceSummary, sourceRideIds[], sourceClaimIds[],
  limitations[], ruleVersion
},
excludedSamples[], privacyFlags[]
```

所有数值、状态和趋势先由确定性聚合规则生成；LLM 只解释已生成字段，不能选择样本、重算趋势、改变能力状态或填补缺失维度。

## 5. 质量门与状态

每个能力维度依次通过：

1. 数据质量门：来源、覆盖、时间顺序、值域和设备状态合格。
2. 场景解释门：暂停、缺口、异常、路线/坡段和环境限制已识别。
3. 可比性门：窗口、路线类型、坡度、设备、体重和个人基线在允许范围。
4. 样本门：达到该维度最低独立记录/区段数，不能把同一活动重复切片充数。
5. 稳定性门：方向或模式在多个样本中具有一致证据，不由单个异常值主导。

首版状态建议为：

- `not_established`：样本或可比性不足，不形成长期结论。
- `provisional`：达到最低样本门，但证据范围仍有限，只能写“初步显示”。
- `established`：多次可比记录、质量稳定且模式重复，可说明该能力已形成稳定证据。

`confidence` 单独使用 `low|medium|high`，表示判断可信度，不是骑行水平分数。是否开放更高低的能力阶段词，需要经过人群基准与样本校准，不能直接由 `confidence` 替代。

## 6. 前端模块

入口建议位于首页或个人页，名称为“骑行能力”；单次骑行详情只提供“查看本次能力证据”或跳转到支撑记录，不把能力画像作为第四个详情 Tab。

首版页面内容：

1. **能力概览**：显示已建立和仍在积累的维度数量，不显示综合总分。
2. **多维能力画像**：每个维度展示状态、可信度、有效样本数、比较窗口和证据摘要。
3. **变化趋势**：仅在可比性门通过时展示该维度随时间的变化，不混合不可比路线或设备。
4. **证据记录**：允许查看支撑该维度的骑行记录或区段，并回到单次详情。
5. **仍需积累**：说明缺少多少同类有效样本或哪项基线尚未建立，避免只显示空状态。
6. **下一步方向**：只指出值得继续观察或练习的一个方向；训练计划必须进入独立专项模块和安全 Gate。

无长期证据的维度可以显示“尚未建立”及可操作的积累条件，但不得显示虚构状态、零分或用户排名。用户删除记录、撤回权限或更新体重/FTP 后，应触发能力画像重算并保留规则版本。

## 7. “我的水平”如何回答

首版优先回答“相对过去的自己是否变化”和“哪些能力证据已经形成”。“我的水平属于什么水平”需要另加经过校准的人群基准，至少明确：参考人群、性别/年龄是否分层、设备和协议、路线/环境条件、样本量、更新时间与适用范围。

在基准未建立前：

- 不使用百分位、人群排名或“新手/进阶/高手”。
- 不用均速、总里程、累计爬升或路线爬坡等级替代人的水平。
- 可以按维度说明相对本人历史的变化和长期证据状态。

人群水平分层应作为 `AI-CAP-01B` 独立研究与校准任务，不能由 LLM 常识直接制定。

## 8. 与训练、分享和对话的衔接

- 单次解读给一条低风险方向性建议；能力画像只提供长期值得关注的方向。
- 个性化多周训练计划需要目标、时间、主观感受、健康筛查、规则引擎和专业审核，另设专项 Gate。
- 分享默认只分享用户主动选择的维度、状态和脱敏证据，不暴露完整历史、精确位置或健康数据。
- **对话 Agent（`ride_chat_v1`）只读解释**：经只读工具 `get_capability_profile` 读取已发布画像快照（维度状态、可信度、样本数、证据 ID），回答"我的能力怎么样了""哪个维度在进步"类问题；解释必须引用快照内证据，样本不足或不可比时按对话 D1 降级说明缺口。对话不得绕过聚合规则重新评估水平、不重算趋势、不推断人群分层。工具随 `AI-CAP-01E` 专项 Gate 通过后接入（见《AI骑行伙伴_Agent架构设计.md》第 10 节）。
- **触发类写操作**：对话中的"重新评估我的能力"不直接执行重算，而是经 `trigger_capability_recompute` 受理后由规则引擎异步执行并回填能力页面；受理需幂等、显式 UI 确认（页面确认组件，不接受对话文本作为确认）、独立授权与专项评测，未过准入前按"域内但能力不足"模板回应。数据变化（记录删除、权限撤回、体重/FTP 更新）触发的自动重算走服务端事件，不经对话。
- 交付形态为**能力页面 + 对话可问**：页面承载画像可视化、证据回溯与确认交互，对话只做只读解释与触发引导，不在气泡内复述完整画像（PRD 6.7）。

## 9. 分阶段任务

- `AI-CAP-01A`：冻结能力维度、纵向样本合同、可比性矩阵、状态和降级规则。
- `AI-CAP-01B`：调研并校准人群水平参考框架；未通过前只做相对本人画像。
- `AI-CAP-01C`：建立脱敏纵向 fixture、确定性聚合器和回放测试，不接生产历史。
- `AI-CAP-01D`：设计并预览独立能力页面，验证用户是否理解状态、可信度和证据。
- `AI-CAP-01E`：接入真实持久历史、权限/删除重算和独立 AI 测评。

本设计与单次骑后解读分别验收、分别发布和回滚；单次解读通过不代表能力评估可以上线。

## 10. 待确认事项

1. 首版能力状态是否只用“尚未建立/初步形成/证据稳定”，还是先仅显示事实与可信度。
2. 比较窗口优先采用近 30 天、90 天，还是按同路线/同训练场景动态选择。
3. 首版是否完全不做人群水平，只上线“相对自己”的多维能力画像。
4. 哪些环境字段（温度、风、跟骑、RPE）作为后续可比性必要输入。
