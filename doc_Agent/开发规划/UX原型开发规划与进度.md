## 当前开发流程与场景合同（2026-11-02）

**明确用户场景 → 定好输入输出合同 → 补充 Agent 能力并接入界面 → 端到端验收。** 架构底座范围及出口见[Agent 开发规划 §2](VIBE_CODING_Agent_开发规划_v2.md)。底座通过后按场景一→二→三→四→五推进，既有 UX-P 批次作为实现和验收证据来源，不重置已验收结果。

- 场景一＝UX-P1（UX-01/02/07）：首次进入与资料／目标；复核已有入口和 Agent 信息补充的缺口。
- 场景二＝UX-P2（UX-03/04）：同步、真实导入与单次解读；第三方同步保持模拟边界。
- 场景三＝UX-P3（UX-05/06/16）：近期整体、记录选择和知识追问；在新架构中复核当前联调能力及实际范围支持。
- 场景四＝UX-P4（UX-08～11）：真实计划生成、补信息、草案版本、规则硬门、确认启用与周计划。
- 场景五＝UX-P5（UX-12～15）：今日卡片、确认关联记录、真实执行评估与确认调整。
- UX-P6 为五场景后的整体一致性检查；UX-16/17/18 贯穿每个场景。

每个场景开工时在本文件补齐合同卡，再改代码；具体 schema、枚举和版本在 AI-Spec 维护。本节只是填写模板，不能作为业务合同已定稿的证据：

1. **场景与入口**：用户目标、触发动作、起始数据和计划状态、复用与缺口。
2. **输入**：话语／表单／动作、对象唯一 ID、日期范围、已知资料、缺项、草案版本与确认信息。
3. **输出**：reply、choices/artifact/quickActions（按场景需要），结构版本、数据／知识依据、状态变更和下一入口。
4. **副作用与异常**：写入与确认边界、幂等、缺项／歧义／无数据／失效引用／服务失败的恢复方式。
5. **端到端验收**：从实际页面入口到结果及保存状态，覆盖正常与关键异常、手机／桌面、返回与刷新；记录真实／模拟／未验证部分及证据。

单节点、任务级测评暂缓，必要时再决策是否建集。已有评分集和本地检查用例保留，不要求为本轮先扩集、冻结或批量跑分；工程检查与场景端到端验收继续。真实模型未验证时如实记录，替身结果不算模型能力通过。

## 技术实施原则

- 开工前读取适用 `AGENTS.md` 与本项目 `node_modules/next/dist/docs/` 的相关指南，再修改 Next.js 代码。
- 复用当前 Next.js／React 项目、页面壳、骑行仓储、资料接口、导入解析、图表及解读组件，不建立平行产品。
- 伙伴作为默认入口；骑行与我的作为另两个主入口。计划详情单独页面，深度解读继续抽屉。
- 已有真实能力保留并复用；第三方平台继续明确模拟。计划生成和执行评估随场景四／五补真实能力；已有模拟只能预览，不能替代场景能力验收。
- 原型明确标识演示环境，允许预置资料、骑行记录与新增数据一起参与分析、统计和计划演示，不建设额外数据隔离机制。提供空白状态切换；清除资料后不自动重新填入。真实用户使用或真实平台接入前再处理数据归属与隔离。
- 需要展示多条骑行记录卡片时，使用堆叠卡片：一次完整展示一条，后方露出卡片边缘；上滑下一条、下滑上一条，支持滚轮、上下按钮与键盘替代，显示当前位置／总数。单条保持普通卡片；切换卡片只浏览，不触发 AI、不暗中选择记录；只有点击该卡片动作才使用它的唯一 ID。同步／导入完成回执仍只显示结果及记录页入口，不恢复记录卡片平铺。
- 对话动作需要明确记录／计划／日期引用，读取时验证可用性；不能仅依赖展示文字猜测对象。
- 个人资料、目标、计划及待确认内容保持一致状态；计划确认针对当前草案版本，重试不能重复启用。
- 预置的周期判断、歧义和修改分支仅用于预览，场景四需通过真实生成链路和规则硬门验证。
- 不在开发验证中擅自发起付费模型评测；复用真实 AI 链路的验证遵循现有专项授权规则，未运行的部分如实列出。

## 场景实施映射（历史批次 ID 保留）

### UX-P1 页面骨架、首次进入与个人资料

- 设计映射：UX-01、02、16、17、18；UX-07 的计划目标归 SCN-04。
- 范围：伙伴／骑行／我的导航，默认伙伴；可切换的新用户空白状态；资料卡片与聊天补充确认；个人页面统一查看与修改身体资料。
- 开始前核对：演示记录合并路径、资料接口与表单预置、会话创建方式，以及聊天资料写入的现有边界。
- 出口：空白状态下能够开始引导、跳过、补充资料及进入计划制定，刷新可恢复已确认信息；有数据状态可合用预置与新增数据，演示环境标识明确，原有记录与导入能力可达。
- 预览：首次打开 → 补资料 → 聊天修正并确认 → 查看“我的”；进入制定计划后再补本次目标；同时检查跳过与返回。

### UX-P2 平台同步与单次查看、解读衔接

- 设计映射：UX-03、04，依赖 UX-P1。
- 范围：四个平台模拟关联、历史范围与增量同步、结果及异常状态；真实文件导入；仅展示结果说明及骑行记录页入口，复用记录页、详情和现有解读抽屉。
- 出口：模拟同步有明确标识；文件真实导入可用；重复及失败可理解；原对话可继续，所选记录与解读一致。
- 预览：连接平台 → 同步 → 记录详情 → 深度解读 → 返回原对话；另查重复文件、授权失效和失败重试。

### UX-P3 近期表现、记录选择与知识追问

- 设计映射：UX-05、06、16，依赖 UX-P2。
- 范围：默认近 30 天综合回答与实际范围、多记录以实体卡片堆叠展示，支持上下滑动切换（底部提示、可见计数和上下按钮按用户要求移除），查询截断时链接全部记录；选择记录；指标释义、结论追问、来源与不能回答的表达。
- 出口：整体分析与单次对象清晰切换；同日多条不混淆；新记录不自动开新对话；无图表任意选区解释。
- 预览：近期表现 → 选某次 → 解释指标 → 追问该次 → 查看依据；检查无记录、仅一条、不可比及知识未覆盖。

### UX-P4 计划补充信息、草案、确认及详情

- 设计映射：UX-08、09、10、11，依赖 UX-P3。
- 范围：卡片／聊天补缺，周期由 Agent 判断且不确定先问，无历史允许自述入门草案；真实生成与修改、处方规则硬门；当前版本按钮确认生效；独立计划详情页与顶部紧凑周计划。
- 出口：无固定默认周期；一个当前生效计划；确认前不进入正式训练安排；修改与重复确认状态正确；已完成历史保留。
- 预览：补缺 → 确认周期 → 草案 → 修改 → 启用 → 顶部周计划 → 点击当天打开详情；检查无历史、失败、旧版本与已有计划替换。

### UX-P5 今日训练、记录关联、评估及简单调整

- 设计映射：UX-12、13、14、15，依赖 UX-P4。
- 范围：进入应用的今日卡片；候选记录推荐和用户确认关联；基于实际计划与记录的执行评估；直接搁置、核实记录缺失及建议调整；自然鼓励与提醒。
- 出口：同日不重复刷屏；完成与执行质量分开；数据不足不强评分；不建跳过／暂停／恢复流程，不自动补课或改计划，无应用外推送。
- 预览：今日安排 → 同步或选记录 → 确认关联 → 评估 → 继续追问；另演示休息日、直接搁置、缺训核实及接受调整建议。

### UX-P6 全旅程一致性与原型收口

- 设计映射：UX-01～19，依赖 UX-P1～P5 用户验收。

- 出口：五条主旅程可演示；已排除功能未重新出现；能力清单与实际实现一致；用户逐页验收通过。

## 验证与验收规则

- 依据变更运行类型检查、相关自动化测试及必要构建；不为纯视觉低风险调整编写镜像测试。
- 重点验证真实文件导入回归、资料确认保存、上下文对象唯一性、草案确认版本与幂等、空白状态切换及演示环境标识。
- UI 每批提供本地可交互地址与简短检查路径，进行手机宽度和桌面宽度检查；截图按需，不以日志代替页面预览。
- 开发状态、检查结果及用户验收只写入总进度文件；本文只定义验收要求。未运行检查不得记录为通过。
- 未解决问题保留证据、影响与下一步，不把原型行为作为真实平台或 Agent 工作流已上线的证据。

## SCN-01 首次进入：实施合同

- 入口：原伙伴欢迎消息、用户说“第一次使用／如何开始／完善资料”、主动陈述资料；无真实注册登录。
- 输入：已有 text/summaries/choice；服务端读取本人身体资料和可见记录，不让客户端声明已完成。AI 结合问题与会话理解资料、引导及概念问答；单位、多值和未知值有歧义时先追问，参数与范围由服务端校验。
- 输出：已有 reply 加 profile_proposal（待保存字段与已保存值）或 onboarding（个人资料、记录、制定训练计划入口）。第03项固定为“制定训练计划”，点击向同一 Agent 发起制定请求。骑行目标不作为独立设置，也不在个人资料表单展示；仅在 SCN-04 制定计划时收集本次目标。
- 副作用：聊天资料提案不保存资料，核对后调用原 profile PUT。计划目标通过 prepare_training_plan.patch.goal 进入待核对计划信息，确认信息、生成草案、启用分开；不再写独立 ux.goal。旧目标编辑引用只引导制定计划，不恢复独立编辑器。
- 恢复：待确认资料、计划信息与导入记录按原仓储恢复；历史独立目标仅保留兼容存储，不读取为当前目标、不自动带入新计划。
- 验收：空白首次进入显示完整引导。即使首次未提问，刷新或返回开场时也只显示欢迎语、三个推荐问题及符合条件的训练提醒。点击推荐问题直接发送，进入对话后收起。另覆盖跳过后直接问知识、资料提案确认／取消、单位澄清、未知 FTP／最大心率和个人资料无目标表单。计划内目标收集、读取、修改与旧目标隔离见 SCN-04。结果只见总进度。

## SCN-02 同步／导入与单次深度解读：实施合同

- 场景：用户从原对话主动同步或导入记录，查看该记录的摘要／分析／数据及深度解读，关闭或返回后继续原对话；平台四选一仍为模拟，FIT／GPX 真实解析。
- 入口与输入：现有同步抽屉、平台关联页和文件表单；自然语言由统一 AI 理解后调用 prepare_ride_import({}) 提供同一入口，不预先按关键词触发。导入／同步明确绑定起始 conversationId，记录访问与解读使用唯一 rideId。
- 输出：AI 的 ride_import 入口；明确新增／重复／失败数量，最多附一个“查看骑行记录”按钮跳转 /import；聊天、平台及文件完成区域不平铺记录，历史回执也采用简洁展示。深度解读沿用 /api/ride-analysis、现有校验与 InterpretationSheet，查询记录卡片／记录详情默认使用同一配置引擎。模型不授权真实平台同步，也不自动上传文件或生成解读。
- 对话连续性：成功回执写回起始对话；返回时定位来源消息或回执，当前可输入的会话保持活跃。回执恢复按事件 ID 去重；单条记录也不隐式当作分析对象。用户点击解读或详情才记为明确记录选择，后续追问沿用该 ID。
- 解读与副作用：只在用户打开或明确重新解读时运行；绑定记录、本人相关资料、引擎及规则版本复用已验证解读，刷新／跨入口不重复付费生成。重新解读绕过成功缓存；失败保留记录，可重试。未通过校验或演示绕过校验的结果不能作为已验证成功缓存。
- 异常：非法／过大／损坏文件及失败重试、相同文件去重、无新平台记录、部分失败重试、取消／授权失效／断开；删除／不可见记录、错配响应、无模型／超时／数据不足均明确说明，不展示错误记录或模拟成功解读。
- 验收：原对话 → AI 同步入口／直接点击 → 平台模拟或真实文件 → 简洁回执 → 跳转骑行记录页 → 查看同一记录 → 深度解读与来源 → 返回续聊 → 刷新恢复；覆盖缓存命中、资料变更使缓存失效、失败重试与多对话归属，检查手机和桌面。工程及实际模型证据只记总进度；不建设节点／任务测评集。

## SCN-03 近期表现、记录选择与知识追问：实施合同

- 场景与入口：用户询问近期表现，先综合范围内全部可见记录；再通过堆叠卡片选择某次或打开既有解读／详情，继续指标与知识追问。保留单 Agent 主链，不新增日期表单、固定依据面板或常驻记录提示。
- 输入：text／summaries／choice 继续沿用；最近默认截至今天近 30 个上海日历日；支持近 7 天、近 30 天及明确起止日期，含首尾日、最多 365 天。显式日期范围独立于当前单次对象，不能改用最新记录日期或静默截短；不完整或不合法范围由 AI 澄清。
- 输出：根据同一次范围查询的事实说明实际日期、记录数及可靠概况，按需检索知识后给解释与限制。记录卡片只能来自该查询结果，多条堆叠，服务端返回明细最多 20 条，截断时说明并链接全部记录页；切换仅浏览，明确动作才选定 ID。
- 上下文：点选后依据该 ID 读取新事实；中性知识追问承接记录与概念，返回整体时清除单次继承屏障，新会话不继承具体对象。同步不自动选择，失效对象提示重新选择，不暗换最新。
- 工具异常：仅已注册工具的参数合同错误可在原模型／工具总预算内纠正一次；原调用不执行、不作为证据，不由服务端猜自然语言或放宽参数。未知工具、越权 ID 直接拒绝；再次参数错误如实说明请求处理失败，不声称用户问题不被支持。
- 知识与边界：一般解释必须使用实际命中条目；个人结论还需个人数据依据，知识未覆盖、无记录、单条不能判断趋势、不可比及服务失败分别说明。来源用可核实的条目名称在回复内说明，不新增独立知识面板；不计算或编造 FTP／能力等级／训练处方。
- 验收：整体 → 自定义范围 → 同源卡片 → 选旧记录 → 指标／知识追问 → 解读／详情返回 → 刷新／新会话；覆盖跨午夜日期边界、同日多条、空／单记录、知识未覆盖、越权、参数纠正及故障。工程检查及实际模型证据仅记录总进度，节点／任务专项测评暂缓。

## SCN-04 训练计划：实施合同（2026-11-03）

- 入口去重：无生效计划时，顶部不再单独展示“制定训练计划”；通过欢迎卡片第03项或直接对话发起。已有待确认草案入口和生效周计划条继续按真实状态展示。

- 入口：聊天自然语言或“制定训练计划”；由统一 Agent 查询计划上下文、准备信息及提出草案，不增加关键词执行分支。复用资料、已有计划信息和近期可见记录，本次目标仅在该流程内补充，不读取旧独立目标；无记录允许用户自述基础，FTP／功率计可未知。
- 信息：目标、开始／结束日期、每周可用日期与各天时长、基础、条件及需避开的日期；周期无固定缺省，AI 可提出有依据的待确认周期，不确定先问。表单与聊天维护同一版本化信息，生成前必须点击“核对信息并生成草案”；准备信息不启用计划。
- 目标选择：信息卡使用下拉选择，不要求手写目标。提供保持规律骑行、提升耐力／完成长距离、提升速度、提升 FTP、提升爬坡表现、备赛；未选择时保留空占位，不自动替用户选第一项。对话或旧计划已有具体目标时保留其完整内容为当前选项，不用关键词归类或丢掉距离／赛事说明；更多具体诉求可在对话中补充。
- 生成：AI 选择分周阶段与每周训练类型／时长；规则扩展为按日训练／休息与步骤。周期最长366日，每周至多6次，强度与周量、时间、恢复日、已知不适和数据条件经领域硬门；拒绝结果可修正，不展示为可执行计划。规则参数为原型保守策略，不冒充临床或普适安全标准。
- 新计划入口：用户明确重新制定时，由 AI 先读取并介绍现有生效计划的目标、周期和训练概况，再调用 prepare_training_plan 的 startNew:true，返回“制定计划”卡片。卡片提示新计划确认并启用后覆盖原计划；此前原计划继续生效。重新核对信息与不适情况，不能复用旧确认直接生成日程，也不拿当前计划卡片代替入口。
- 生命周期：放弃或被后续草案取代的未启用草案显示“未采纳”；删除、取消或被新生效计划覆盖的版本显示“已终止”。仅生成新草案不终止当前生效计划；历史详情只读，已终止和未采纳版本均不能直接启用。
- 草案与修改：结构化卡片含目标、日期、版本、周次数／时长、依据及限制。查看独立详情，按周／天展示；历史卡片保留所引用版本，主按钮查看该历史计划，不跳转到最新版。聊天可更新信息或重新提出日程，修改产生新版本且仍待确认；失败保留信息与既有草案。
- 启用：仅详情页“确认并启用计划”按钮发起版本／内容绑定确认；同一时间一份生效计划。展示未来安排替换范围，历史与完成记录保留。并发旧版本、过期凭据和重复请求由共用确认服务与真实事务处理，聊天中的“可以／不错”不能启用。
- 显示与恢复：对话顶部展示紧凑周计划，点击打开独立详情并定位日期，切周与返回保留对话；过期未有完成记录只显示“尚未记录完成情况”。真实执行评估、记录关联和调整归 SCN-05，不提前冒充已完成。
- 存储：本人计划、草案、确认凭据、回执和审计使用原子事务，跨进程有效；空白演示视图与资料变更后需重新核对，不复活旧确认。账户删除清除计划数据。
- 验收：无历史自述基础与有记录复用；缺项／周期确认→真实生成→规则拒绝与修正→修改旧版本→明确启用／重复确认→刷新周计划和详情；验证替换、故障、归属、跨进程事务、手机和桌面。进度仅在总进度维护，专项建集与节点／任务测评暂缓。

## SCN-05 今日训练与执行评估：实施合同（2026-11-03）

- 今日入口：读取本人生效计划和上海日期，仅在首次进入或过期后的开场区展示可更新的今日卡片。首条消息发出后收起开场区。反复进入、刷新及同步不会追加开场卡片到历史。训练、休息、已关联／已评估、未开始／结束、无计划或仅草案分别说明，不把未上传当缺训。应用内展示，不新增外部推送或跳过／暂停管理。
- 关联输入：明确 planId/version/date，推荐同上海起始日的本人可见候选；多候选沿用堆叠，展示日期、来源、距离与时长。上传／同步后回到原对话、重新读取候选，由本人选一条并明确确认，不能自动关联全部记录或由聊天同意代替确认。
- 写入与恢复：关联绑定计划、日期、记录内容指纹及当前关联 revision，通过共用确认事务提交。更换记录先清空旧结论，失败保留已确认关联；版本、数据、可见性变化使旧评估失效，不能继续冒充有效结果。已替换的未来安排、未来日期或未生效草案不能关联执行。
- 评估输出：规则计算计划与实际时长、可比功率及现有传感器事实；完成情况与执行质量分开。当前标准化记录没有计划步骤／圈段对应关系，明确不能核实逐步执行；缺传感器、未知 FTP、只有含停顿总时长时不强判完整完成或评分。AI 在同一 Agent 循环中根据实际事实和按需检索知识给亮点、差异、建议；事实已就绪但模型失败要分开呈现，可重试，不显示旧结论。
- 反馈与调整：疲惫或不想练先接受、理解；无记录不能认定缺训，不自动补课或改安排。用户明确要求调整时沿用 SCN-04 草案及再次确认，不新增未经审查的缺训阈值或自动训练加量。
- 计划删除补充：详情页明确选择并确认删除某版本，绑定确切版本与当前状态，重复确认幂等；生效指针及待确认指针相应更新，旧卡片显示“已终止”，可查看该版本历史详情。保留骑行原记录、已有关联／评估与审计，不以聊天表达删除。
- 验收：今日展示去重与状态变化→同步／上传或已有候选→本人选择确认→事实对比与实际 AI 反馈→更换／删除记录失效→失败重试→刷新／返回／新会话；覆盖旧版本、越权、并发、重复确认、计划删除及历史保留。保留工程和端到端检查，节点／任务测评与建集继续暂缓；结果只见开发进度。
