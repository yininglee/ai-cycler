# Agent_Name: Cycler

# Agent角色定位

Cycler是「**教练型伙伴**」：能就任意一次骑行展开分析；不清楚的知识、数据不乱编乱猜，能进一步向用户澄清；能交付一份可查看、可确认、可执行的计划；能把骑行运动知识讲清楚；日常会督促训练和提供情绪价值；让用户感觉是专业、可信的。

# 用户场景故事

### **核心用户画像 A ：骑行运动爱好者（追求锻炼、提升和进阶）**

特征：16-35岁，具备有氧运动基础，热爱骑行运动。每周都会进行3～4骑行训练，包括平路巡航、跑山爬坡等训练，关注运动健康、训练数据和锻炼效果，经常参加骑行活动/骑行比赛。

痛点：进阶数据看不懂，缺乏专业指导。

场景一：用户第一次注册并打开Cycler，Cycler此时没有关于用户的任何信息、记忆和数据记录，Cycler询问并引导用户完成个人资料填写/引导骑行运动记录迁移、导入/引导制定骑行训练目标；

场景二：用户完成一次骑行运动了，运动数据存在了码表对应的APP里，用户主动点击“同步骑行记录”，记录同步到Cycler，用户进行该骑行数据查看，并且点击查看深度解读和基于本次数据解读的建议

场景三：用户问Cycler”最近骑行表现怎么样？“，Cycler查询用户最近的骑行记录的数据，并结合知识库进行分析和回答，并且展示该记录的深度解读按钮，用户可自行查看深度解读。如果最近的骑行记录中有多条骑行数据记录，则结合多条记录进行分析、解读，用户可选择某条记录查看深度解读。若用户看到不懂的数据或概念，询问/追问Cycler，Cycler能基于知识库给出准确的回答，Cycler如果不能确定正确与否或不具备某个能力，不回答并能说明原因。

场景四：用户想要制定骑行训练计划，点击“制定训练计划”或和Cycler说“制定训练计划”，Cycler能根据最近的骑行记录表现、用户信息资料、骑行训练目标等给出训练计划，训练计划在对话中以卡片的形式展示。用户点击卡片查看计划，点击确认计划即写入训练计划中。如果用户没有说明目标、没有说明必要的信息，需要展示「信息补充界面卡片」和追问，用户可以填写信息或直接回答补充信息。训练计划按周展示在对话界面顶部，用户点击进入查看计划。

场景五：用户打开Cycler，Cycler在对话界面中发来“今天计划”并以卡片形式展示计划。用户查看训练计划，按照本日训练计划完成了今天的训练后，点击该卡片上的上传/同步训练记录，上传今天的骑行数据。Cycler基于上传的数据和计划进行分析评估。

## Agent触点与能力

### 本轮设计基线（2026-11-01）

以下内容来自本轮逐项审核。上方用户故事保留为原始需求；其中“第一次注册”在本轮仅指首次进入体验，**不包含真实注册／登录**。下文以 UX-01～UX-19 标识设计项。

- 当前分支：`codex/m7-ux`。直接在已有实现上开发原型，不建设独立的原型产品或另一套页面。
- 复用资料保存、FIT／GPX 导入、骑行详情、图表、知识问答和深度解读等已有能力；真实链路的边界继续沿用。
- 第三方平台授权与同步、训练计划生成和执行评估等尚未实现的能力，在同一套产品界面中用明确标识的模拟能力演示。
- 当前为未投入使用的原型，允许预置资料、预置骑行记录与新增数据一起用于分析、统计和计划演示，不额外建设数据隔离机制。明确标识演示环境，支持切换到空白状态验证首次进入；真实用户使用或真实平台接入前，再处理数据归属与隔离。
- 本轮交付 UX 方案和可交互原型，不等同于全部后端能力已交付。设计确认、开发自检、用户验收分别记录。
- 原型按旅程分批预览，每批用户验收后再进入下一批。执行顺序见[UX 原型开发规划与进度](开发规划/UX原型开发规划与进度.md)。

### UX-01 首次进入与欢迎引导 · 设计已确认

- 首次进入场景从空白状态开始，Cycler 介绍作用及尚不了解用户的情况；原型提供空白状态切换，其他演示流程可直接使用预置和新增数据。
- 提供完善个人资料、导入骑行记录、设置骑行目标三个入口，允许跳过并直接提问。
- 保存引导进度，返回后继续，已完成步骤不重复要求；需要必要信息时再按需询问。
- 原型统一标识演示环境；有数据状态允许预置记录参与基线和汇总，空白状态用于验收首次引导。

### UX-02 个人资料收集与补充 · 设计已确认

- 复用年龄、身高、体重、最大心率和 FTP 五个字段，首次均可跳过；最大心率、FTP 支持“不知道”，不要求猜值。
- 使用资料补充卡片和聊天双入口，资料页统一查看、修改已保存内容。
- 聊天识别的资料先展示待保存内容，经用户确认后写入；歧义、单位不明及与已有值冲突时先澄清。
- 只追问当前任务需要的信息。用户不愿提供或不知道时说明影响，继续可完成的部分。
- 区分用户提供和系统估算，展示来源与更新时间。保存失败保留输入，清除后不自动补入演示值。

### UX-03 骑行导入与平台同步 · 设计已确认

- 文件导入与连接运动平台并存。原型使用通用“运动平台”占位，不绑定具体供应商。
- 首次连接：选择平台 → 授权说明 → 模拟授权 → 选择历史记录范围 → 模拟同步；后续同步新增记录并展示上次同步时间。
- 展示新增、重复、失败数量，支持查看记录和失败重试；覆盖取消授权、授权失效、无新记录和断开连接。
- 从对话发起后可回到原对话，明确刚接入的记录；成功后可查看骑行、进入深度解读。
- 文件导入复用现有真实能力，完善处理中、重复记录、失败与重试反馈；数据缺少心率或功率等时说明分析范围。
- 模拟授权、模拟同步全程可辨识；同步样例可与现有及新增骑行数据共同用于原型演示。

### UX-04 单次骑行查看与深度解读 · 设计已确认

- 保留摘要、分析、数据三个页签；分别承载快速概览、图表与比较、具体指标。
- 入口统一为“查看深度解读”。对话记录卡片与骑行详情复用同一解读抽屉，关闭后保留原位置。
- 卡片、详情与解读保持记录身份一致，展示日期、名称及核心数据，避免分析错记录。
- 首屏呈现整体评价、重点发现和下一步建议；维度与证据按需展开，限制就近展示。
- 解读提供继续追问入口，携带当前记录及所选结论；具体边界见 UX-06。
- 区分生成中、生成失败、数据不足和已有解读，失败可重试。原型需覆盖这些状态。

### UX-05 近期表现与多记录选择 · 设计已确认

- “最近表现怎么样”先综合分析范围内记录，不要求先选一次。回答涵盖概况、有证据支持的变化、限制与建议。
- “最近”默认近 30 天，展示实际起止日期和参与记录数；支持近 7 天、近 30 天、自定义范围，用户已指定时遵从其范围。
- 参与分析的列表默认展示最近 5 条，其余查看全部。每条含日期时间、名称、距离、时长及心率／功率可用性。
- 可选某条继续问或打开深度解读，明确当前对象，并支持回到近期总览。
- 指代不明时询问近期整体还是某一次；同日多条用时间和摘要区分，不擅自选最新。
- 无记录引导同步；仅一条不判断趋势；不可比时只陈述可靠事实，不强判进步或退步。

### UX-06 知识解释与连续追问 · 设计已确认

- 支持直接提问、指标旁简短释义、解读结论旁“继续追问”。追问携带明确的记录和结论上下文。
- 先通俗解释是什么、怎么看，再按需展开与本次骑行的关系；区分一般知识与个人结论。
- 追问承接当前概念和记录，多个可能对象时澄清。
- 提供可展开的知识依据，展示实际引用条目、来源与限制；只有可核实的原文链接才展示链接。
- 区分知识未覆盖、个人数据不足、问题歧义、服务失败。可答部分先答，其余说明原因和下一步。
- **不纳入图表任意点选／框选某点或某段后的解释**。原型用预置内容演示新增交互，已有知识问答能力继续复用。

### UX-07 骑行目标设置 · 设计已确认

- 仅管理一个当前主要目标，次要诉求作为补充说明，不设计多个独立目标并行管理。
- 目标选项：保持规律骑行、提升耐力／完成长距离、提升 FTP、提升爬坡表现、备赛、自定义。
- 首次引导、主动表达目标、制定计划时均可进入；按目标补距离、期望时间或赛事等必要信息，不重复询问已知内容。
- 确认摘要后保存，可查看、修改或暂不设置。目标变化后提示是否调整已有计划，计划更新另行确认。
- 不额外建设目标生命周期管理；训练搁置采用 UX-14 的简化方案。

### UX-08 计划生成前的信息补充 · 设计已确认

- 复用已确认目标、资料、近期记录和可用负荷信息，只补缺项，允许纠正。
- 收集目标与必要日期、开始日期、每周可训练日期及各天时长、近期骑行基础、训练条件与需要避开的日期。
- 卡片填写和聊天交替更新同一份待确认信息，歧义或冲突先询问。
- 目标、时间安排和可用训练基础需要明确；FTP、功率计等允许不知道／没有，计划表达适配已有条件。
- **无历史记录时，允许补充自述骑行基础后生成入门草案**，标注依据，不推测能力或 FTP。
- 生成前展示摘要，可修改、退出和稍后继续；生成草案与计划生效分别确认。

### UX-09 计划草案生成、展示与修改 · 设计已确认

- **不设置固定默认周期**。用户指定时遵从；未指定时 Agent 结合目标、日期、基础、近期表现与可训练时间决定并说明依据；不确定时先询问用户确认。
- 多长周期均按周展示。对话草案卡片含目标、日期范围、本周次数和总时长及查看入口，标注待确认。
- 详情按周、按天展示训练／休息，包含目的、时长、与数据条件匹配的强度表达、步骤和注意事项。
- 说明制定依据和限制，区分个人记录与自述信息。
- 支持通过修改入口或聊天调整，说明变更，更新后仍待确认。
- 生成失败保留输入，支持重试。未实现的生成能力以预置方案模拟，并覆盖询问周期分支。

### UX-10 确认与生效 · 设计已确认

- 草案待确认，可查看、修改或放弃；查看详情后通过“确认并启用计划”按钮生效。
- 确认针对当前版本；修改后重新确认，旧卡片标明已更新并指向最新版。
- 同一时间一份生效计划。重叠时确认前说明替换哪些未来安排，保留已完成训练与执行记录。
- 成功显示已生效及查看本周入口；失败保留草案可重试，重复点击不生成多份计划。
- “不错”“可以看看”等聊天表达不触发生效。本轮使用明确按钮作为启用入口。

### UX-11 顶部周计划与详情 · 设计已确认

- 对话顶部紧凑展示本周日期、七天训练／休息安排并突出今天。
- **点击打开独立计划详情页**，点击某天时定位当天；详情支持切换周次、回到本周和查看完整周期。
- 显示未开始、待完成、待评估、已完成等状态。过期无记录时显示“尚未记录完成情况”，不直接推定缺训。
- 从详情解释或调整时携带计划和日期进入对话，返回保持消息与浏览位置。
- 无计划、草案待确认、未开始、已结束均有对应提示。**不提供跳过、暂停、恢复管理**。

### UX-12 今日计划卡片 · 设计已确认

- 用户进入对话时根据生效计划展示今日卡片，含日期、训练名称、目的、时长、强度概要。
- 查看训练打开计划详情并定位今天；同步／上传入口复用 UX-03。
- 休息日、完成后、无计划、未开始和已结束均展示相应内容。
- 同日重复进入复用卡片，安排或执行状态变化后更新，不重复刷屏；主动询问也能获取。
- 今天没时间时可直接搁置；明确要求调整时才进入调整流程，不强制选择处理方式。
- **主动提醒限于打开应用后的应用内展示**，不纳入手机推送、短信等应用外提醒。

### UX-13 记录关联与执行评估 · 设计已确认

- 从当天训练发起同步、上传或选择已有记录，系统推荐当天候选，用户确认后关联并评估。
- 多候选展示日期时间、距离和时长，不把当天所有记录自动关联。
- 分开表达完成情况与执行质量，比较有依据的时长、强度和训练步骤；数据不足说明不可判断部分，不强给完整评分。
- 评估卡片含计划与实际、亮点、差异、建议，提供查看评估、骑行记录、继续追问入口。
- 选错记录可更换并更新结果；评估失败保留关联可重试，避免继续展示失效结论。
- 后续计划调整建议须经确认生效。原型模拟评估，已有记录和解读能力复用。

### UX-14 训练搁置与调整建议 · 设计已确认（简化后）

- **允许直接搁置训练，不设计跳过、暂停、恢复操作或管理流程。** Cycler 简短接受，不要求额外管理。
- 不自动补课，不堆积漏掉的训练，不自动修改计划。
- 缺训较多时结合近期执行和用户反馈，核实安排是否合适，再建议调整；不设未经审核的固定缺训阈值。
- 无同步记录先确认是否已训练但未上传，不把数据缺失当成缺训。
- 用户接受调整建议或主动要求后展示新草案，确认才生效。
- 本项取代初稿中关于跳过、暂停、恢复及其强制选择的建议，并约束其他设计项。

### UX-15 日常陪伴与反馈 · 设计已确认

- 鼓励具体有据，数据支持才说进步，不泛泛夸奖。
- 表达疲惫、失落或不想训练时，先简短理解，再按需建议，不立即追问一串问题。
- 自然提醒、接受搁置，不指责、不反复催促；缺训较多沿用 UX-14。
- 专业但自然，先易懂后深入，避免术语堆积、空泛口号和过度亲密称呼。
- 融入现有对话，不增加情绪打卡、连续签到、积分或陪伴任务。

### UX-16 对话连续性与已知信息复用 · 设计已确认

- 已保存资料、目标、训练安排与生效计划持续复用，不重复填写。
- 当前骑行、计划日期和概念承接追问，有歧义才澄清。
- **同步记录后继续原对话**，更新数据，不自动开启新对话。
- 主动新建对话保留个人基础，不擅自继承旧对话的具体分析对象。
- 临时表达不直接变成长久事实；涉及长期安排或资料变化时按已确认流程保存。
- 不建设独立记忆管理中心，保留对话历史、新对话和资料修改入口。

## 界面信息架构优化

### UX-17 页面结构与入口 · 设计已确认

- 主导航：**伙伴／骑行／我的**，默认进入伙伴对话。
- 伙伴：顶部紧凑周计划，对话承载今日计划、记录、补充信息和草案等卡片。历史和新对话在页头。
- 骑行：日历、记录、同步、文件导入和近期表现；PMC 等已有能力保留为次级入口。
- 我的：个人资料、当前目标、常用训练安排、运动平台连接。
- 计划详情是独立页面，不增加主导航项；骑行详情保留三个页签，深度解读为抽屉。
- 首次引导融入伙伴页，现有介绍页不再独占“今日”导航。返回对话保留位置。
- 产品和 Agent 名称统一为 Cycler，操作名称统一。

## 交互设计

### 统一交互边界

- 查看、解释与修改请求尽量复用当前记录／计划／日期上下文；对象不明时询问。
- 确认个人资料和目标后保存；计划草案必须通过明确启用按钮生效。
- 重试不丢输入、不重复创建实体；模拟能力和真实结果可辨识。
- 训练搁置保持简单，不引入跳过、暂停或恢复流程。
- 原型分批开发和验收见 UX-19 及对应进度文件。

## 界面视觉设计

### UX-18 视觉与基础交互规范 · 设计已确认

- 沿用浅灰背景、白色卡片、黑色主按钮和圆角控件，减少装饰渐变与过大宣传标题。
- 统一卡片字号、间距、按钮规则，以标题、内容和文字状态区分用途。
- 一张卡片一个主要动作，其余为次级按钮或文字入口。
- 状态不只靠颜色表达，待确认、生效、同步中及数据不足就近显示。
- 等待提示符合当前任务，不显示不可验证的百分比；错误说明原因和可做的下一步。
- 手机优先，输入框与导航不遮挡，长内容按需展开，按钮便于触控；桌面保持合适宽度。
- 本轮确认规范方向，具体页面在原型中逐页预览验收。

## 原型交付与验收

### UX-19 交付方式 · 设计已确认（调整后）

- 交付本文完整 UX 方案及可点击原型，覆盖首次引导、骑行同步与解读、近期分析与解释、草案生成确认、今日训练与评估五条旅程。
- **直接改造当前分支的已有页面和导航，复用已有真实能力**；不建设独立原型入口或复制另一套产品。
- 仅对未实现能力提供模拟，接入同一界面，后续可替换为真实实现。
- 明确标识演示环境，允许预置和新增数据共同使用；少量演示状态切换放在正常用户流程之外，方便审核空白新用户、已有计划、数据不足及失败状态，不额外建设数据隔离机制。
- 分批完成主要旅程，完成一批即提供可体验预览，反馈修正后再进入下一批。
- 不纳入真实注册登录、真实第三方接入、多独立目标、跳过／暂停／恢复管理、图表任意选区解释及应用外提醒。
- 本项以用户提出“在原来已实现的基础直接开发原型”后的“同意”为最终交付方式确认，替代早先独立原型入口建议。
