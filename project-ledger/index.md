# AI 骑行伙伴台账导航与事实源目录

> 用途：供人工导航和定位事实源，不承载新的项目事实，也不是Codex每次恢复的必读文件。
>
> 维护规则：只更新当前指针和链接；历史过程写入 `progress-ledger.md`，历史决策写入 `decision-log.md`。

## Codex恢复入口

Codex直接读取[当前状态](current-status.md)，再按其中链接读取当前工作项最近日志和证据；只有事实归属或链接不清晰时才读取本索引。

## 新日志最小格式

每条新日志只写“这次新增了什么”，没有发生的字段直接省略：

```markdown
## LOG-YYYYMMDD-NNN｜工作项与变化摘要

- 元信息：日期 / 阶段 / 工作项；状态：`STATUS`
- 本次变化：
- 验证摘要与证据链接：
- 下一步：
```

仅在实际发生时增加变更文件/资源、版本变化、用户反馈/验收、风险/阻塞或`NOT_RUN/PARTIAL`。测试失败也记录；不把“代码已完成”写成“用户已验收”；不复制完整测试表、版本矩阵或决策理由。

## 工作项启动审查规则

每个`ITEM`开始前必须审查三份开发依据，但默认只读取相关章节：

- PRD：当前工作项直接相关的产品行为和边界；
- 研发指南：对应实现、AI规则和测试章节；
- 版本路线图：对应模块行、版本范围和Gate；
- 台账/评审/决策：当前状态、最近证据和已确认取舍。

只有进入新阶段、重大架构/安全/数据边界变化、用户改方向、实质冲突、3–5项阶段巡检或Gate/发布准备时，才全文复查三份主文档。审查结果使用启动审查卡记录章节引用，不复制全文。
