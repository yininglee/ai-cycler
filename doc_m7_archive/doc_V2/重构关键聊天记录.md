### 2. 先定义分析问题与证据矩阵

- 爬坡表现与地形负荷
- 心率负荷与区段响应
- 功率输出、稳定性和峰值
- 踏频策略
- 跨传感器配合，例如同一窗口内心率与功率的共同变化

### 3. 当前时序特征不足以支持严谨判断

现有均值、标准差、CV 和前后四分之一差值能支持粗粒度概括，但当前算法按**采样点等权**计算，没有统一处理时间/距离权重、停歇排除、传感器时间对齐、连续窗口或区段内表现。因此不能仅凭这些特征可靠支撑稳定性、后程保持、爬坡节奏或跨传感器配合等结论。[当前特征计算](</Users/liyining/Documents/ChatGPT/AI骑行伙伴-指导版_0827-m4-refactor-agent-capabilities/src/domain/ride-features.ts:163>)

### 4. “覆盖所有可用数据”需要明确定义边界

目前上下文没有覆盖所有已解析、可计算的数据：例如 `elevationLossM` 被排除；原始时序点和部分连续性信息没有作为分析证据系统性组织；当前 AI API 没有传入 Profile 或历史快照；一些已经构建的 Claims 也没有对应维度，最后不会进入模型。[上下文构建现状](</Users/liyining/Documents/ChatGPT/AI骑行伙伴-指导版_0827-m4-refactor-agent-capabilities/src/domain/ride-analysis-context.ts:321>) [AI API 当前调用](</Users/liyining/Documents/ChatGPT/AI骑行伙伴-指导版_0827-m4-refactor-agent-capabilities/app/api/ride-analysis/route.ts:105>)

但“所有可用数据”应限定为：**解析器支持并进入标准化记录的数据、经过验证的派生证据、调用方实际提供且授权使用的 Profile/历史，以及本次检索到的知识证据**。FIT 文件理论上可能出现、但解析器未映射的字段不属于当前可用证据，也不能假设 AI 能读到。

还要区分“所有证据都可被使用”和“把所有原始采样逐点发送给模型”。后者可能带来体积、隐私和噪声问题。合理目标是保留完整、可追溯的证据池；为各分析问题生成充分的结构化证据包和必要的时间序列摘要，而不是无差别堆入全量原始点。

### 5. 原子能力需要从字段目录升级为分析问题目录

现有原子能力主要回答“有没有距离、功率、心率、FTP 等输入”。它还不能完整回答“能不能分析功率稳定性”“能不能分析爬坡区段心率响应”等具体问题；部分区间/训练负荷能力还存在规则状态与独立分析规则之间不一致。[当前能力集合与依赖](</Users/liyining/Documents/ChatGPT/AI骑行伙伴-指导版_0827-m4-refactor-agent-capabilities/src/domain/atomic-capabilities.ts:13>) [规则状态](</Users/liyining/Documents/ChatGPT/AI骑行伙伴-指导版_0827-m4-refactor-agent-capabilities/src/domain/atomic-capabilities.ts:214>)

建议把“原子能力”重定义或扩展为**分析能力目录**。例如区分 `power_mean`、`power_stability`、`power_peak`、`climb_performance`、`heart_rate_load`、`power_hr_relationship`。每项返回可用、部分可用或不可用状态，以及支持它的证据、质量和原因。目录应覆盖产品承诺的分析问题，同时允许未来扩展，不能宣称覆盖所有可能的运动科学分析。

### 6. Claims 应是证据载体，不再成为第二道隐形筛选

第 6 节定义数据来源和派生结果；Claim 是把其中可引用事实包装成带来源、质量、规则版本和证据 ID 的单元。它们不是额外数据源。当前 Claim 有复合文本和结构化字段不完全对应的情况；解读计划又只挑少数 Claim，造成证据损失。

新规则应要求：单条事实 Claim 表达一个可验证结论；关系 Claim 明确参与事实、窗口对齐方式与允许表达的关系；每个分析维度引用完整的适用 Claim 集合，而不是只取第一个匹配项。仍需通过质量规则和输出校验约束“能说什么”，避免把“完整证据池”误变成“模型可自由推断”。

### 7. 加入运动科学知识库可行，但要与骑行事实分开

这条方向**可行，也有价值**：骑行数据提供“这次发生了什么”，历史和 Profile 提供“相对于谁/什么基线”，运动科学知识提供“这些事实通常如何解释、有哪些限制和安全边界”。

建议把知识库作为独立、可检索的知识证据层，而不是混入骑行 Claim 或把整库直接拼进 Prompt。每个知识条目需保留来源、版本/日期、适用人群与条件、证据强度、限制和检索 ID；AI 输出中的科学解释或建议应能追溯到相应条目。知识库不能补造本次骑行未记录的事实，也不能把相关关系说成因果。

最终上下文建议分成四类、保持来源隔离：

- 本次骑行事实与确定性分析
- 历史比较证据
- 用户 Profile
- 运动科学/标准知识证据

当前链路不传 Profile/历史且排除 `history_change`，所以“历史默认进入、可选”需要作为明确的新产品规则贯穿 API、资格、证据矩阵和输出校验；只有历史可比性通过时才默认纳入，用户可选择不使用。[当前历史输入限制](</Users/liyining/Documents/ChatGPT/AI骑行伙伴-指导版_0827-m4-refactor-agent-capabilities/src/ai/ride-interpretation-input-v04-candidate.ts:74>)
