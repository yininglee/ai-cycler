## 0. 结论

把对话伙伴从「**问一句、答一段话**」升级为「**教练型伙伴**」：能就任意一次骑行展开分析、能在需要时让用户做选择、能交付一份可查看可确认的东西（计划）、能把知识讲清楚。v1 分析的六个任务簇全部保留；v2 新增的是**交互形态**需求（选择 / 交付 / 确认），并据此把结构目标从"16 条路由"收敛为"三个平面"。

**继承 v1 不变的**：层级 1 扩工具面 + 训练监督单点升级（不上多 Agent）；派生指标由规则计算、模型只引用；训练处方必须过硬门与人工确认；业务指标口径（服务覆盖率 ≥80%、计划采纳率 ≥60%）。

## 1. 用户与核心场景（2026-11-02 按 UX 收敛）

用户为骑行运动爱好者；角色是专业可信的教练型伙伴。当前场景事实源为 [UX Design](UX%20Design.md)，原六条任务旅程收敛到以下五个完整用户场景，能力诉求继续保留。

1. 首次进入：引导补充个人资料、导入记录和设置主要目标，允许跳过与恢复；当前不包含真实注册登录。
2. 骑后导入／同步：用户导入 FIT／GPX，或在平台连接页手动检查新骑行，随后查看记录、深度解读与建议。顽鹿提供受控单账号联调入口，其他平台及未启用联调的顽鹿仍为模拟。正式平台接入另行验收。[第三方同步技术方案](开发规划/Cycler_第三方骑行自动同步技术方案.md)
3. 近期表现与追问：综合多条记录和知识回答，展示同源记录卡片，可选择单次解读、连续询问概念；无依据时说明限制。
4. 训练计划：用户核对目标、周期、可用时间和基础后发起草案生成。安排结合近期骑行、身体资料和可核实的训练知识，经过规则校验后可查看和修改。用户明确确认当前版本后启用，按周展示。
5. 今日训练与评估：会话开场时随欢迎语和输入引导展示今日安排。用户上传／同步或选择已有记录，确认关联后评估完成情况与执行质量，调整须另行确认。

五个场景共用一个聊天窗口。距上一轮结束满 24 小时后自动开启新一段会话，欢迎语、推荐问题及符合条件的今日训练卡随开场展示。旧消息默认收起，可在消息顶部按需回看，新一轮从新的上下文开始。会话入口与展示规则见 [UX Design](UX%20Design.md) 的 UX-12、UX-16 和 UX-17。

先完成共用 Agent 架构底座，再逐场景执行“明确场景 → 输入输出合同 → Agent 能力与界面 → 端到端验收”。单节点、任务级测评暂缓，必要时另行决策建集；工程检查、证据校验、处方硬门和用户确认保留。详细范围与顺序见[开发规划](开发规划/VIBE_CODING_Agent_开发规划_v2.md)。

## 2. 产品体验原则（从旅程推导，五条）

1. **指哪打哪**：用户指哪条记录就分析哪条；指不清就给选项让用户点；**绝不偷偷替用户选"最近一次"**。
2. **轻问轻答、重问走工作流**：随口一问给快速摘要；要完整解读时进入骑后解读工作流（两者文案要能区分"摘要"与"完整解读"）。
3. **交付物先确认后生效**：计划这类会影响行为的产物，生成后只展示，用户确认才写入。
4. **说的每个数字都有出处**：继续执行"模型不计算、只引用"。
5. **说不出来就明说**：数据没有 / 知识没覆盖 / 能力没做，各有一句诚实话术，禁止编造。

> **开发口径**：原则 1=rideRef 参数化（`{date|ordinal|rideId}` + 候选列表 + 不缺省取最新）；原则 2=单工具轻链路 + `quickActions` 按钮挂深度分析；原则 3=`confirm_write` 动作 + 确认令牌；原则 4/5=数字白名单与降级话术（现役机制沿用）。

## 3. 能力需求（四类，对应系统可调用的四类能力）

| 类别 | 用户视角 | 承载内容 |
|---|---|---|
| **工具（Tools）** | "查我这次的数据""我的 FTP 是多少" | 单次骑行指标、数据可用性、身体基线、训练负荷、路线形状 |
| **知识库（RAG）** | "为什么练区间""什么是乳酸阈" | 骑行科学知识 7 维度；回答必须引用真实条目 |
| **数据查询** | "哪次最远""最近三个月骑了多少""比上个月呢" | 跨记录筛选、排名、阈值、聚合、对比 |
| **工作流** | "帮我排训练计划""重新深度分析这次" | 多步有规则的流程：计划生成（含硬门与确认）、骑后解读重跑 |

**选择**（让用户挑记录/挑目标）不单列一类，因为它是一种**交互动作**，附着在上述能力之上。

## 4. 结构要求（产品视角的三平面）

| 平面 | 用户能感受到什么 | 为什么需要 |
|---|---|---|
| **控制平面** | 危险话题秒回固定话术；"一共骑了多少"秒出精确数字；写操作被明确拒绝 | 这些**不能**交给模型：急症要零延迟，总里程要精确，安全边界要确定 |
| **认知平面** | 获准且需要模型的请求进入统一链路，由 Agent 结合本轮问题和会话决定查询、澄清或准备交付物 | 前置分类聚焦安全、隐私、注入和明确域外边界，复合业务问题可在同一轮处理 |
| **交互平面** | 能被追问"哪一次"并看到列表；能点按钮进深度分析；计划能确认 | 现在系统只会"回答"，不会"发起选择/交付/确认" |

> **开发口径**：三路由 `stop / deterministic / agent_loop`；动作 7 值（+`select`/`produce_artifact`/`confirm_write`）；choice 状态槽位；artifact 交付通道；`quickActions` 按钮。详见 [AI-Spec v2](AI-Spec_对话Agent能力规约_v2.md)。

## 5. 成功指标

以下指标保留为后续观测与正式放行目标；当前以架构及逐场景端到端验收为准，不要求为这些指标先建测评集，也不以原型演示推断真实采纳率。

| 类别 | 指标 | 目标 | 来源 |
|---|---|---|---|
| 业务 | 对话服务覆盖率（有效服务占比） | ≥80% | v1 继承 |
| 业务 | 训练计划采纳率（确认生效/生成） | ≥60% | v1 继承 |
| 业务 | 周活跃对话轮次（训练季） | ≥5 轮/周 | v1 继承 |
| 业务（新） | 记录选择成功率 | 点选/指认后答对记录的比例 ≥95% | v2 场景① |
| 业务（新） | 深度分析入口使用率 | 轻答后进入深度分析的比例（观测，不设门） | v2 场景② |
| 模型（内部） | 工具调用合法率 / 数字溯源通过率 / KB 引用命中率 | ≥95% / ≥98% / ≥90% | v1 继承 |

## 6. 边界与护栏（P0，不变）

- **训练处方**：强度不超个人基准关系、周量增幅受限、每周恢复日、伤病禁忌强制转就医——规则硬门先行，模型不可越过；确认制生效。
- **健康边界**：急症/用药/带伤训练请求 → 固定话术 + 就医引导（现役）。
- **隐私**：只看本人数据；精坐标、原始轨迹、文件名、他人记录永不出现（现役投影机制沿用）。
- **写操作**：全项目首个写路径（计划确认）必须带确认令牌与审计留痕。

## 8. 后续正式放行（与当前开发验收分开）

影子 → 只读全自动（覆盖率 ≥70%）→ 计划人机协作（采纳率 ≥60%、硬门违规 0）→ 监督自动化。v2 的交互能力（①②⑤⑥）属只读阶段；训练计划（③④）属人机协作阶段。
