# AI 解读 V2 测评方案设计（RIDE-AI-EVAL-01）

- 状态：初稿，待用户确认 8 个决策点（见文末）后冻结
- 版本：v0.3（2026-10-07）
- 关联：[AI解读证据体系与上下文重构_PRD](AI解读证据体系与上下文重构_PRD.md)（第 11 节 AC-11、第 12 节发布门）、[AI解读分析上下文业务规则说明](AI解读分析上下文业务规则说明.md)、[VIBE_CODING_开发规划](VIBE_CODING_开发规划.md)（RIDE-AI-EVAL-01/EVAL-02）
- 版本栈基线：Prompt v2.6.0（含输入压缩 PD-AI-24、知识软关 PD-AI-25、interpretation 类型 PD-AI-27）/ 模型提供方规则 v2.1.0（temperature 0.3、思考关闭，PD-AI-23）/ 输入 schema v2.3.0 / 输出 schema v2.2.0（新增 interpretation 结论类型）

## 1. 目标

用一次全新的冻结评测 Run 回答三个问题：

1. V2 解读的事实质量是否达到 PRD 发布门；
2. "同输入偶发失败"（偶发 `REPAIR_FAILED`）的真实发生率是多少、要不要处理；
3. 关闭思考链（PD-AI-23）后质量有没有明显下降。

评测结论是是否申请 V2 放量的依据，不复用 V1 旧盲评（T002-V04）结论。

## 3. 四项盲评指标与阈值（1–7 分制，延续 V1 盲评口径便于对照；双人盲评）

| 指标 | 评什么 | 阈值（PRD 12.1 发布门） |
|---|---|---|
| 事实忠实度 | 每个数字和断言能否在详情页或证据里找到出处 | **硬门问题 = 0**；均分 ≥ B0 确定性基线 |
| 不确定性表达 | 该说"估算/数据有限"时是否说了；不该确定的是否装确定 | 无"无证据确定断言" |
| 洞察价值 | 是否讲出数据里真实的东西，而非放之四海皆准的空话 | 均分 ≥ 4 |
| 行动性 | 建议是否可执行、有证据支撑 | 均分 ≥ 4；"建议无依据"计为 0 |

**自动指标**（程序统计，不依赖人工）：首轮通过率、一次修复通过率、最终降级率、四类零容忍断言数（稳定无波动/提升无历史/恢复无 TSB/计划无计划，必须为 0）、延迟分布（P50/P95）、每次成功解读的令牌成本。

**interpretation 类型相关观测（PD-AI-27 阶段性策略）**：①"解读深度"——统计每维度 interpretation 断言数量与占比，盲评时评估其是否产生真实洞察（区别于空话），对照"洞察价值"指标；②"先松表达门"越界率——统计 interpretation 断言内出现无证据稳定性/恢复/历史/计划表述的占比，作为是否把表达门加回 interpretation 的判据（见 §8）。

## 4. 偶发 REPAIR_FAILED 失败率量化（本 Run 核心纳入项）

- 方法：8 条可解读样例每条连续调用 5 次（同输入重复，复用 V1 定向诊断采样工具思路），共 40 次真实调用，在 PD-AI-23 参数（temperature 0.3、思考关闭）+ 知识软关（PD-AI-25）+ interpretation 类型（PD-AI-27）下进行。
- 统计口径：首轮通过率 / 修复后通过率 / 最终降级率，及失败错误类型分布（高光未绑证据、数字不在证据内、claimIds 类型错误、稳定性措辞、跨 Claim 合计违规、AI_TIMEOUT 供应商偶发超时等）。
- **高频合计需求观测（PD-AI-28）**：统计跨 Claim 合计类违规的具体形态（模型试图合并哪些指标——如"Z5-Z7 合计占比""前中后段合计"），据此决定证据层批量补哪些确定性派生 Claim（`provenance=calculated` + `formulaVersion`），把高频需求从"模型违规"转为"合法供给"。
- 阈值建议（三档，待用户定）：**最终降级率 ≤ 5% 放行**；5–15% 需定处理方案（本地删句方案 B / claimId 去数字化方案 C / few-shot 再议）；> 15% 停下，换模型或加强提示后再测。

## 5. 反例集（自动回归，验证"防线不漏"）

构造 6 类已知违规输出（稳定性无波动、能力提升无历史、恢复无 TSB ≥ +5、计划完成无计划、因果表述、历史对比措辞），每类 2–3 条变体，全部必须被输出校验器拦截，漏拦 = 0。反例集随全量测试长期运行（对应 PRD 风险表"迁移前运行反例集"）。

## 6. 双人盲评流程

- 材料：8 条可解读样例 × 2 份解读（V2 真实输出 vs B0 确定性文案），随机顺序、不标来源，共 16 份。
- 评分表：四项各 1–7 分 + 硬门问题计数 + 一句话总评。
- 评审组成（待用户定）：方案 a——您 + 一名评审各评一遍；方案 b——您对同一批材料间隔至少 48 小时两次独立评分。

## 7. Run ID 与版本留痕规则

- Run ID 格式 `EVAL-V2-R{序号}-{冻结日期}`，首个为 **`EVAL-V2-R01-20261007`**。
- 每次 Run 记录完整版本栈（Prompt / 模型提供方规则 / 输入 schema / 输出 schema / 证据规则版本 / 样例集版本）。
- 样例集或版本栈任一变化 → 必须开新 Run，不跨 Run 混用结论。

## 8. 实验选项（不阻塞主 Run，主 Run 出分后视结果决定是否做）

- few-shot 合规示例：Prompt 追加 1 个完整合规输出示例，对比首轮通过率（既有决策的实验项）。
- 思考开/关对比：若盲评"洞察价值/行动性"均分较思考开启时期下降明显（建议 > 1 分），恢复思考重测。
- 知识开/关对照臂（PD-AI-25 遗留决策）：同一批样例跑"知识附带 vs 知识软关"两种输入，对比盲评"事实忠实度/洞察价值"均分，用数据回答"知识转述到底有没有洞察价值"，据此决定知识层长期去留。
- interpretation 表达门加回条件（PD-AI-27 阶段性策略）：若 interpretation 断言内无证据稳定性/恢复/历史/计划表述占比超过阈值（待定），则把表达门加回 interpretation（连同具体射程一并定）；未超则维持"先松"。
- 缓存命中率实测（S2-07 遗留，2026-10-07 并入本方案）：同一案例 9 次重复调用，在硅基流动账单核对 `prompt_cache_hit_tokens` 占比——PD-AI-24 已剥离缓存杀手、同案例 prompt 字节级稳定，预计命中后输入成本降至约 40%；随 EVAL-01 批量执行顺带完成，不单独跑。
- 性能口径（采纳 AUDIT-01 建议）：只观测记录延迟与成本，不设 V1 旧"8 秒"目标；V2 长骑行数十秒属新产品节奏。

## 9. 发布门对照（EVAL-02 执行后出结论，对照 PRD 12.1）

事实硬门问题 = 0；事实忠实度 ≥ B0；四类零容忍断言 = 0；允许修复时总调用 ≤ 2 次、不可修直接降级零修复。全部达标 → 申请 V2 放量；任一不达标 → 按失败类型定处理方案再开新 Run。

## 10. 待用户确认的决策点

1. 样例集 10 条构成是否认可（尤其 2 条"预期拦截/降级"样例）；
2. 失败率三档阈值（≤5% / 5–15% / >15%）是否认可；
3. 盲评组成选方案 a（您+另一人）还是方案 b（您两次独立评）；
4. 40 次真实调用的成本是否接受；
5. 两个实验（few-shot、思考对比）放在主 Run 之后是否认可；
6. 解读深度——"洞察价值"是否细化为观测 interpretation 断言的占比与真实洞察（还是维持四项指标不变）；
7. 知识开/关对照臂（PD-AI-25 遗留）是否纳入 EVAL-01 实验；
8. interpretation "先松表达门"的越界占比阈值——多少算超、超了就把表达门加回 interpretation。

确认后本方案冻结，进入 EVAL-02 执行。
