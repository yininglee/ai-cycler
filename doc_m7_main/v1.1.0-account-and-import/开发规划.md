# Cycler 1.1.0 账号与第三方骑行导入开发规划

## 阶段一 · 账号与数据隔离

1. 沿用仓库的 Node SQLite 运行环境。新增账号及会话表，邮箱唯一。使用带随机盐的 scrypt 存储密码摘要，保存会话令牌的哈希和过期时间。注册和登录限流，退出撤销当前会话，删除账号撤销该账号的所有会话。
2. 在 Next.js 请求入口校验注册账号会话。未登录页面请求跳转到账号页，业务 API 返回 401。路由和服务继续以服务端会话的 owner ID 查询及写入。旧访客会话无法进入应用。
3. 使用账号页处理登录和注册，从「我的」进入账号管理。登录后复原站内目的页面。浏览器内聊天历史、草稿和导入回执按账号使用独立存储键。覆盖直接访问、跨设备登录、不同账号访问和退出会话的回归用例。

## 阶段二 · 顽鹿与行者导入

1. 两个入口复用文件导入服务，为新记录保存平台标识。沿用单文件 50 MB 校验和同一 owner 的文件内容哈希去重。
2. 顽鹿继续复用已落库的同步适配器和数据归属校验。配置绑定的 owner 可主动连接、同步和断开。其余用户可导入平台导出的文件。
3. 行者增加 OAuth 发起、一次性 state 回调、服务端凭据保存及刷新。回调使用发起授权时的 Cycler 登录会话。手动同步时从公开运动列表筛选最近骑行，按 Cycler 账号、行者账号和活动 ID 去重。使用行者网页 FIT 导出接口，当前实测现有 OAuth 令牌可用。下载仅接受行者返回的预期存储地址，复用 FIT 解析并保留脱敏后的标准化数据。已同步的摘要可保留原记录 ID 并补全，新记录无法读取 FIT 时保存摘要。
4. 覆盖有效文件、重复文件、来源标记、OAuth state 错误与重放、跨账号访问、令牌失效、限流及同步中断。解绑取消进行中的拉取，保留已完成导入的记录。运行类型检查、完整测试和生产构建。

### 顽鹿批量文件导入

1. 顽鹿页接受一个 ZIP 或多个 FIT。批量入口使用 `POST /api/rides/import/onelap-batch`，在路由内校验 Cycler 账号会话和请求来源。该入口直接接收上传请求，避开 Next.js Proxy 默认的 10 MB 缓冲限制。
2. 每批最多 200 个 FIT 和 100 MB 上传文件。ZIP 最多接受 1000 个条目，可导入的 FIT 解压总量最多 256 MB。先校验 ZIP 目录，再逐个读取 FIT，复用现有解析、来源标记与账号内 SHA-256 去重。只保留标准化骑行数据。
3. 批量结果返回新增、重复和失败数量、失败文件及原因。独立保存每条成功记录，整个批次重试时已有文件自动跳过。测试覆盖跨入口去重、子目录、部分失败、账号隔离及真实 HTTP 上传超过 10 MB 的 ZIP。真实 OTM 导出样本待联调。

## 联调与部署

首期沿用单实例和持久数据目录。生产部署使用 HTTPS，注册行者回调地址与应用凭据。顽鹿真实同步沿用已有联调配置。需由持有许可的测试账号验证真实骑行的数据覆盖、平台权限及重复导入结果，再向用户开放连接入口。

使用 Cycler 邮箱账号联调顽鹿时，先在测试实例上注册账号，再由服务端操作者查询该账号的内部 ID，并填入 `ONELAP_SYNC_OWNER_ID`。在项目根目录运行以下命令，用已注册的测试邮箱替换示例中的地址。命令使用当前实例的 `LOCAL_DATA_DIR`，默认读取项目内的 `.local-data`。

```sh
node --env-file-if-exists=.env.local --input-type=module -e '
  import { findAccountCredentials } from "./src/auth/account-store.ts";
  const account = findAccountCredentials(process.argv[1].trim().toLowerCase());
  if (account) console.log(account.id);
  else {
    console.error("当前实例没有这个账号");
    process.exitCode = 1;
  }
' rider@example.com
```

行者同步配置使用行者开发者后台创建的第三方应用 ID 和密钥。将 `XINGZHE_CLIENT_ID`、`XINGZHE_CLIENT_SECRET`、`XINGZHE_REDIRECT_URI` 和至少 32 字符的随机 `SESSION_SECRET` 放在服务端 `.env.local`，设 `XINGZHE_SYNC_ENABLED=true` 后重启服务。[行者开放平台接入说明](https://developer.imxingzhe.com/docs/intro/)

行者后台的「网站」和「授权回调域」都按完整 URL 校验。在同一台机器联调时，「网站」可填 `http://127.0.0.1:3001/`，「授权回调域」可填 `http://127.0.0.1:3001/api/platform/xingzhe/callback`。这两个值通过网页表单校验，仍需用真实行者应用验证保存和授权。将 `XINGZHE_REDIRECT_URI` 配成与后台一致的完整回调地址，并通过 `http://127.0.0.1:3001` 登录 Cycler。访问与回调使用同一主机名，以便回调带上原 Cycler 会话。从其他设备联调，或行者后台限制保存本机地址时，使用 Cycler 的 HTTPS 访问地址和对应回调。

从「运动平台与导入 → 行者」点击「连接行者」，在行者完成只读授权后返回 Cycler，再点击「立即同步」。本人列表应出现带行者来源的骑行。有可用 FIT 的旧摘要应补全原记录，二次同步应计为重复。同步过程中在另一标签页断开连接，可验证进行中的拉取停止。

参考 [版本迭代规划](../AI_Cycler_版本迭代规划.md)。

## iGPSPORT（迹驰）接入调研与联调计划

资料核对日期为 2026 年 11 月 22 日。现有平台目录已有 `igpsport` 标识，注册账号的专属导入入口仍需开发。 [Cycler 平台目录](../../src/ux/platform-catalog.ts)

1. **获取样本。** 优先通过 USB 从支持的码表的 `iGPSPORT/Activities` 目录取原始 FIT，也可用 iGPSPORT App 下载的 FIT。中国大陆与全球官网分别提供网页登录入口。核对实际账号所在地区、单条和批量导出能力，有条件时对比同一条骑行的设备文件和云端文件。如果历史活动只剩云端副本，可联系官方技术支持 `service@igpsport.com` 询问能否提供 FIT。 [码表手册](https://global.igpsport.com/File/pdf/igs618-%E8%AF%B4%E6%98%8E%E4%B9%A6%E4%B8%AD%E6%96%87%E7%89%88.pdf) · [App 数据说明](https://prod.zh.igpsport.com/service/mobile/api/docs/privacy) · [中国大陆网页版](https://app.zh.igpsport.com/) · [全球网页版](https://app.igpsport.com/)
2. **评估专属文件入口。** 用真实 iGPSPORT 样本验证现有 FIT 解析，包括户外轨迹和文件实际记录的功率、心率或踏频。专属入口可复用多 FIT、ZIP 读取和当前账号内的内容哈希去重。入库标记为 iGPSPORT，保留单条失败结果和成功记录。ZIP 作为 Cycler 接受的上传格式，仍需核实 iGPSPORT 网页或 App 会提供何种导出格式。
3. **申请官方接口。** 向开放平台指定邮箱 `global@igpsport.com` 提交 Cycler 应用名称、120×120 PNG 图标、应用简介、网址、公司主体名称、授权回跳地址 `redirect_url` 和运动数据回调地址 `callback_url`。申请时询问个人开发者是否可用、中国大陆与全球账号覆盖，以及第三方可获批的只读权限。回跳与运动数据回调使用各自的联调地址，待官方确认后再接入。 [iGPSPORT 开放平台申请说明](https://www.igpsport.com/support/app/openapi)
4. **确认云端接口。** 向平台索取授权范围、历史骑行列表和分页、活动明细、原始 FIT 或下载地址及其有效期。确认 `callback_url` 的触发条件、载荷、验签和重试规则，以及授权续期与撤销。公开申请页只确认 OAuth 2.0 和申请字段，历史补拉与原始 FIT 的接口能力待官方文档和联调验证。 [iGPSPORT 开放平台](https://www.igpsport.com/support/app/openapi)
5. **决定同步方式。** 历史列表和 FIT 下载的权限验证通过后，再接入账号连接与手动补拉。若获批接口只提供新活动回调，历史记录继续走文件导入。云端联调至少覆盖一次授权、同一活动重复到达、两个 Cycler 账号隔离，以及撤销后停止取数。

iGPSPORT 官方介绍了绑定 Strava 或 TrainingPeaks 后同步新上传活动的流程。对已有记录的补传和原始 FIT 保真度仍需验证。Cycler 的云端接入优先评估 iGPSPORT 自有开放平台。 [iGPSPORT 官方同步说明](https://eu.igpsport.com/products/ride-pro-box)
